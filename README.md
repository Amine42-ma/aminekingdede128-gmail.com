# KAD-KAD · AI GAME LAB

نواة ذكاء اصطناعي **محلية بالكامل** لتحليل مشاريع الألعاب وأصولها وبناء ألعاب جديدة —
داخل **ملف واحد**: `index.html`.

> لا OpenAI. لا Claude. لا Gemini. لا مفتاح API. لا خادم. لا خدمة مدفوعة.
> تحقّقنا من ذلك آليًا: **صفر طلبات شبكية** أثناء التشغيل وأثناء توليد لعبة كاملة،
> وصفر روابط خارجية في الشيفرة.

## التشغيل

نزّل `index.html` وافتحه — يعمل من `file://` بلا خادم وبلا إنترنت.
على الهاتف: افتحه من متصفح الهاتف، أو أضفه إلى الشاشة الرئيسية ليعمل كتطبيق.

المتصفحات: Chrome / Edge / Safari حديثة. يلزم IndexedDB و WebGL و WebAudio.

## بمقاس الهاتف — في كل مكان

الواجهة **هاتفية دائمًا**، لا تتمدّد على عرض الحاسوب:

- على الهاتف تملأ الشاشة، والتنقّل شريط سفلي يُستخدم بالإبهام.
- على الحاسوب أو اللوحي يظهر التطبيق داخل **إطار هاتف في منتصف الشاشة** —
  نفس التجربة بالضبط، فما تراه أثناء التطوير هو ما يراه اللاعب على هاتفه.

**الألعاب المولَّدة تُلعب بالإبهام:** كل لعبة تخرج بعصا تحكّم مرئية أسفل اليسار
وزر فعل أسفل اليمين (افصل / إرجاع / عبور / تبديل / تسارع حسب اللعبة).
لوحة المفاتيح تظل تعمل، لكنها ليست الأساس.
الكاميرا في الألعاب ثلاثية الأبعاد تثبّت **المجال الأفقي** وتشتقّ الرأسي منه،
وإلا انكمش المشهد إلى ~29° على شاشة رأسية.

## ما الذي يفعله فعلًا

| القدرة | التنفيذ الحقيقي |
|---|---|
| **قراءة ZIP** | قارئ ZIP مكتوب من الصفر: End-Of-Central-Directory + Local Headers، وفك الضغط عبر `DecompressionStream('deflate-raw')`. يتخطّى `node_modules` و `__MACOSX`. |
| **تحليل GLB / glTF** | محلّل ثنائي كامل: رؤوس الملف، قطع JSON/BIN، accessors، bufferViews، شبكات، مواد، نسيج، حركات، عظام، هرمية العقد، وحساب الأبعاد من `min/max`. |
| **معاينة ثلاثية الأبعاد** | عارض WebGL مكتوب يدويًا (بلا مكتبات): يبني الهندسة من `POSITION`/`NORMAL`، يطبّق مصفوفات العقد، إضاءة وضباب، تدوير وتقريب باللمس. |
| **تحليل الصوت** | فك ترميز بـ WebAudio ثم DSP حقيقي: RMS، ذروة، ZCR، **FFT radix-2 مكتوب يدويًا**، مركز طيفي، انحدار 85%، تفلطح، غلاف زمني، قابلية التكرار → تصنيف من الإشارة لا من الاسم فقط. |
| **تحليل الصور** | قراءة بكسل: أبعاد، شفافية، إنتروبيا، كثافة حواف (Sobel)، **قابلية تبليط** (مقارنة الحواف المتقابلة)، ألوان مهيمنة بـ k-means. |
| **تحليل الشيفرة** | محلّل JavaScript ثابت: إزالة تعليقات/سلاسل مع حفظ المواضع، مطابقة أقواس، دوال وأصناف ودوالّها، متغيرات، استيراد/تصدير، استدعاءات، أحداث، **تعقيد دوري**، كشف تكرار، واستنتاج أنظمة اللعبة. |
| **استخراج المفاهيم** | يحوّل الشيفرة إلى **مواصفات معامِلية** (`vehicle.control`, `camera.follow` …) مع قراءة القيم الحقيقية من الملف (`maxSpeed = 32`). مفاهيم — لا نسخ شيفرة. |
| **الرسم المعرفي** | عقد (أصول/مفاهيم/ميكانيكيات/مشاريع) وحواف مسمّاة، اكتشاف تلقائي للعلاقات بالتشابه المتجهي + الوسوم المشتركة + PMI المتعلَّم، وتخطيط قوى للعرض. |
| **فهم النية** | طبقتان: مصنّف softmax مدرَّب + محفّزات لغوية عربية/إنجليزية. **مقيس بتحقق متقاطع**: الدمج ≈ 84.6% للنية الأولى، ≈ 90% ضمن أفضل ثلاث، على 22 نية. |
| **الجسر ثنائي اللغة** | «أين نظام السيارات؟» يجد `VehicleController.js` عبر توسيع الاستعلام بمعجم المجال عربي↔إنجليزي. |
| **تصميم اللعبة** | فضاء تصميم من **8 محاور** (بنية/حركة/نمو/مورد/خطر/هدف/قيد/التفاتة). بحث فعلي بمئات المرشحين + طفرات، مع **قياس أصالة** صريح مقابل 7 أنماط معروفة وكل لعبة سبق توليدها. |
| **توليد الشيفرة** | مولّد تركيبي: كل قيمة محور تضيف/تحذف دوالًا حقيقية. محرّكان: Canvas ثنائي الأبعاد، و WebGL ثلاثي الأبعاد يحمّل **مجسمك أنت** ويربط **صوت محركك** بالسرعة. |
| **الاختبار والإصلاح** | كل لعبة مولَّدة تُشغَّل في `iframe sandbox` معزول، تُجمع أخطاؤها وعدد إطاراتها، ثم دورة إصلاح: فرضية → ترقيع → إعادة اختبار → **تراجع إن لم يتحسّن**. |
| **مصنع النماذج** | تدريب حقيقي بـ SGD (softmax / logistic متعدد الوسوم / ridge / PMI) داخل المتصفح، مع منحنى خسارة ودقة. |
| **Benchmark & Evolution** | مجموعة تقييم محجوزة ببذرة ثابتة (999) **على مستوى الجملة** (بلا تسريب). الترقية تتطلب تفوّقًا ≥ 0.005 — الأحدث ليس أفضل تلقائيًا. النماذج القديمة تُؤرشف ولا تُحذف. |
| **الذاكرة** | IndexedDB: الملفات كـ Blob، وكل شيء آخر كسجلات. تصدير/استعادة كاملة. |
| **المهام الطويلة** | قائمة مهام تحفظ التقدّم والحالة ونقاط الحفظ وتُستأنف بعد إعادة فتح الصفحة. |

## ما الذي **لا** يفعله — بصراحة

هذه ليست تحفّظات شكلية؛ هي حدود حقيقية للنظام:

- **لا رؤية دلالية.** لا يعرف «ما الذي في الصورة» ولا الشكل البصري للمجسم.
  التصنيف يأتي من أسماء العقد والبنية والنِسب وإحصاءات البكسل — ويُعرض مع أدلّته ونسبة ثقته.
- **ليس نموذجًا لغويًا ضخمًا.** لا يؤلّف نصًا حرًا عن أي موضوع. ردوده مبنية من نتائج تحليل فعلية.
- **لا تدريب عميق.** المتصفح بلا GPU/خادم لا يحتمل ذلك. النماذج هنا خطّية وصغيرة — لكنها **مدرَّبة ومقيَّمة فعلًا**.
- **لا ينفّذ ملفاتك.** التحليل ثابت تمامًا؛ التشغيل حصريًا داخل `iframe sandbox="allow-scripts"` بلا وصول إلى الصفحة أو بياناتها.

## الخصوصية والحقوق

- ملفاتك **لا تغادر جهازك**: لا `fetch` خارجي ولا تحليلات ولا رفع تلقائي.
- كل أصل يُسجَّل بحقل `rights`؛ المشاريع التي تحلّلها تُعامَل **مصدرًا للتعلّم والتحليل فقط**،
  والمفاهيم المستخلصة تُخزَّن كأوصاف معامِلية لا كنسخ من شيفرتك.
- الشيفرة المولَّدة من تأليف النظام نفسه؛ لا تُنسخ إليها شيفرة مشاريعك.

## البنية الداخلية

وحدات منفصلة داخل الملف الواحد:

```
Storage · Tokenizer · Vector · ML · ModelRegistry · ModelFactory · Datasets
Benchmark · Evolution · KnowledgeBase · KnowledgeGraph · AssetLibrary
Analyzers (ZIP · GLB/glTF · OBJ · Audio/FFT · Image · Code) · ConceptExtractor
ProjectAnalyzer · CreativeEngine · ReasoningEngine · GameBuilder
CodeGen2D · CodeGen3D · TestEngine · FixEngine · JobQueue · Chat · NLG · Backup · UI
```

نقاط التوسّع المستقبلية مصمَّمة كواجهات: `TRAIN.run(cap)` و `BENCH.evalModel(meta)` و
`REG.save()` تقبل أي نموذج أكبر لاحقًا (خادم تدريب أو WebGPU) دون إعادة كتابة بقية النظام.

## الفحص الذاتي

الإعدادات ← **تشغيل الفحص**. يشغّل 27 اختبارًا حقيقيًا: المعالج اللغوي، المتجهات،
تدريب softmax/ridge، محلّل الشيفرة، محلّل GLB على ملف مبنيّ في الذاكرة، FFT مقابل
تردد معلوم، دورة تخزين كاملة، **35 تركيبة توليد شيفرة**، تشغيل لعبة فعلي،
وقياس دقة فهم النية بالتحقق المتقاطع.
