# يوسف والعوالم العشرة — مواصفات كاملة للتنفيذ
### لعبة منصّات ثلاثية الأبعاد بمسار ثابت (2.5D) — ملف `index.html` واحد

> هذا الملف هو **دفتر المواصفات التقني**. يُسلَّم كما هو إلى الذكاء الاصطناعي في محادثة
> جديدة ليكتب اللعبة. القسم الأخير (§20) يحتوي البرومبت الجاهز للّصق.

## 1. الفكرة في سطرين

**يوسف** فتى من قرية عربية سُرقت شمسها العشر (عشر جواهر ضوئية) ووُزّعت على عشرة عوالم.
يركض يوسف إلى الأمام عبر ممرّ ثلاثي الأبعاد، يقفز فوق الفجوات، يدوس الأعداء، يتفادى الأفخاخ،
ويستعيد جوهرة في نهاية كل عالم. **100 مرحلة، 10 عوالم، 10 زعماء.**

الشخصية **ليست ماريو** ولا نسخة منه: يوسف نحيل، بشرة قمحية، شعر أسود مجعّد،
قميص أخضر زيتوني، سروال بني بحزام جلدي، **كوفية حمراء** حول الرقبة تطير خلفه أثناء الجري
(هي علامته البصرية المميزة)، وحذاء رياضي أبيض. لا شارب، لا قبعة حمراء، لا بذلة زرقاء.

## 2. نمط اللعب — «الممرّ الثلاثي» (Corridor 2.5D)

هذه نقطة التصميم الأهم، وهي بالضبط ما طلبته:

```
                    ▲ Y (القفز)
                    │
                    │        ╔══════════════════╗ ← حدّ الممرّ (جدار غير مرئي)
                    │       ╱                  ╱
    الكاميرا ●━━━━━━┿━━━━━ ╱  ← يوسف         ╱   عرض الممرّ = 10 وحدات
       (خلف)        │     ╱                  ╱     (Z من -5 إلى +5)
                    │    ╚══════════════════╝  ← حدّ الممرّ
                    └──────────────────────────▶ X (اتجاه التقدّم، لا نهائي إلى الأمام)
```

| المحور | المعنى | الحدود |
|---|---|---|
| **X** | التقدّم للأمام | من 0 إلى نهاية المرحلة (200–600 وحدة حسب الصعوبة). لا يمكن الرجوع أكثر من 12 وحدة خلف الكاميرا |
| **Z** | التحرّك يميناً/يساراً | **مقيّد بصرامة** بين `-trackHalfWidth` و `+trackHalfWidth`. جدران غير مرئية صلبة. عرض الممرّ يتغيّر حسب القطعة (من 6 إلى 14 وحدة) |
| **Y** | القفز والسقوط | لا سقف. السقوط تحت `y = -20` = موت |

**لماذا هذا التصميم ذكي:** يعطي عمق الثلاثي الأبعاد (تفادي جانبي، أعداء تأتي من الجوانب،
منصات على أعماق مختلفة) مع بقاء المستوى قابلاً للتصميم والقياس مثل لعبة ثنائية الأبعاد —
وهذا ما يجعل صناعة 100 مرحلة أمراً ممكناً أصلاً.

**الكاميرا:** منظور الشخص الثالث خلف يوسف مباشرة.
```js
targetPos = player.pos + vec3(-9, +5.5, 0)   // خلف وفوق
camera.position.lerp(targetPos, 1 - Math.exp(-8 * dt))   // نعومة مستقلة عن FPS
camera.lookAt(player.pos + vec3(3, 1.2, 0))  // تنظر أمام اللاعب قليلاً
```
+ اهتزاز (screen shake) عند الهبوط القوي والضرر وانفجارات الزعيم.
+ تراجع الكاميرا للخلف قليلاً عند الركض السريع (FOV من 60° إلى 68°).

## 4. حلقة اللعبة والتوقيت

خطوة فيزياء ثابتة إلزامية — بدونها يختلف ارتفاع القفز بين جهاز 60Hz و144Hz:

```js
const FIXED_DT = 1/120;
let acc = 0, last = performance.now();
function frame(now){
  requestAnimationFrame(frame);
  let dt = Math.min((now - last)/1000, 0.25); last = now;   // تجاهل التجميد الطويل
  acc += dt;
  while (acc >= FIXED_DT){ stepPhysics(FIXED_DT); acc -= FIXED_DT; }
  const alpha = acc / FIXED_DT;
  render(alpha);   // استيفاء بين prevPos و pos لصورة ناعمة
}
```

## 5. الفيزياء والإحساس (Game Feel)

القيم التالية **مضبوطة ومُختبَرة نظرياً** — تعطي قفزة تشبه ماريو الحديث. لا تُغيَّر عشوائياً:

```js
const P = {
  gravity:        -62,    // وحدة/ث²
  jumpVelocity:    19.5,  // → ارتفاع أقصى 3.07 وحدة، زمن هواء 0.63 ث
  runSpeed:        13,    // وحدة/ث (مع Shift: 17)
  strafeSpeed:     10,    // السرعة الجانبية على Z
  accelGround:     90, accelAir: 45,
  frictionGround:  14, frictionAir: 1.5,
  maxFallSpeed:   -45,
  coyoteTime:      0.10,  // يمكن القفز بعد مغادرة الحافة بـ 100ms
  jumpBuffer:      0.13,  // ضغط القفز قبل الهبوط بـ 130ms يُسجَّل
  jumpCutoff:      0.45,  // إفلات الزر يضرب السرعة الصاعدة في هذا
  stompBounce:     13,    // ارتداد بعد دوس عدو
  springBounce:    28,
  invulnTime:      1.4,   // ثواني وميض بعد الضرر
};
```
**مسافة القفز القصوى المحسوبة:** أفقياً `13 × 0.63 = 8.2` وحدة، ارتفاعاً `3.07` وحدة.
→ **قاعدة التصميم الذهبية:** أي فجوة > **6.5 وحدة** أو أي درجة > **2.6 وحدة** = مرفوضة
(هامش أمان 20%). المولّد يرفضها آلياً (§8).

**كشف التصادم:** AABB × AABB مع حلّ **محور بمحور بالترتيب Y → X → Z**.
هذا الترتيب مقصود: يضمن الهبوط على المنصات قبل التصاقك بجدرانها الجانبية.

```js
function resolveAxis(body, axis, boxes){
  for (const b of boxes){
    if (!overlap(body.aabb, b.aabb)) continue;
    const push = minPenetration(body.aabb, b.aabb, axis);
    body.pos[axis] += push;
    if (axis === 'y'){
      if (push > 0){ body.vel.y = 0; body.grounded = true; body.groundRef = b; }
      else          { body.vel.y = Math.min(body.vel.y, 0); }   // ارتطام بالسقف
    } else body.vel[axis] = 0;
  }
}
```

**حالات اللاعب (State Machine):**
`idle → run → jump → doubleJump → fall → land → stomp → hurt → dead → win`
كل حالة لها مدخل/تحديث/مخرج ورسوم متحركة خاصة.

## 9. نظام المستويات — الحلّ العملي لـ 100 مرحلة

**المشكلة:** كتابة 100 مرحلة يدوياً = 100 × 200 سطر = مستحيل في ملف واحد.
**الحلّ:** نظام **هجين** — قطع مصمَّمة يدوياً + تركيب حتمي بالبذرة.

### 9.1 بنك القطع (Chunks)

نصنع **~45 قطعة** مصمَّمة يدوياً بعناية. كل قطعة:

```js
{
  id: 'gap_triple',
  len: 24,              // طولها على X
  diff: 3,              // صعوبتها 1..5
  entryY: 0, exitY: 0,  // ارتفاع المدخل والمخرج (للوصل الصحيح)
  width: 10,            // عرض الممرّ فيها
  tags: ['gap','air'],  // للتنويع ومنع التكرار
  build(x, rng, d){     // d = صعوبة المرحلة 0..1
    return [
      tile('solid',  x+0,  0, 0, 6,1,10),
      tile('solid',  x+11, 0, 0, 4,1,10),
      tile('solid',  x+19, 0, 0, 5,1,10),
      enemy('walker', x+20, 1, rng.range(-3,3)),
    ];
  }
}
```

**فئات القطع (كل فئة 4–6 قطع):**
`start` · `flat` · `stairs` · `gap` · `pillars` · `movingPlat` · `enemyGauntlet` ·
`trapRoom` · `verticalClimb` · `narrowBridge` (عرض 4 فقط) · `wideArena` (عرض 14) ·
`conveyorRun` · `iceSlide` · `waterSection` · `secretRoom` · `checkpoint` · `finish`

### 9.2 المولّد الحتمي

```js
function generateLevel(index){          // index = 1..100
  const rng   = mulberry32(0x59555346 ^ (index * 2654435761));  // بذرة ثابتة
  const world = Math.ceil(index / 10);  // 1..10
  const step  = ((index - 1) % 10) + 1; // 1..10
  const d     = index / 100;            // منحنى الصعوبة 0.01 .. 1.00

  if (step === 10) return buildBossArena(world, rng);

  const target   = 200 + d * 400;              // طول المرحلة 200→600
  const maxDiff  = Math.min(5, 1 + Math.floor(d * 5));
  const pool     = CHUNKS.filter(c => c.diff <= maxDiff && worldAllows(world, c));

  let x = 0, out = [], prevExitY = 0, lastTags = [];
  out.push(...CHUNK_START.build(0, rng, d));  x = CHUNK_START.len;

  while (x < target){
    const cand = pool.filter(c =>
        Math.abs(c.entryY - prevExitY) <= 2.4 &&      // قابل للوصل
        !lastTags.some(t => c.tags.includes(t)));      // منع التكرار المباشر
    const c = rng.pick(cand.length ? cand : pool);
    out.push(...c.build(x, rng, d));
    x += c.len + rng.range(2, 5);                      // فاصل
    prevExitY = c.exitY; lastTags = c.tags;
    if (x > target * 0.5 && !out.hasCheckpoint) out.push(checkpoint(x));
  }
  out.push(...CHUNK_FINISH.build(x, rng, d));

  applyWorldTheme(out, world);        // ألوان + استبدال أنواع (ثلج/حمم/…)
  scaleDensity(out, d);               // كثافة الأعداء 0.3 → 1.0
  if (!isSolvable(out)) return generateLevel(index + 1000);  // خطة بديلة
  return out;
}
```

**نفس البذرة = نفس المرحلة دائماً** لكل لاعب على كل جهاز. المرحلة 47 هي المرحلة 47 للجميع.

### 9.3 مدقّق قابلية العبور (إلزامي)

قبل عرض أي مرحلة، محاكاة سريعة: من كل منصّة، هل يمكن الوصول للتالية بقفزة قصوى
(8.2 أفقياً × 3.07 عمودياً، مع خصم هامش 20%)؟ إن فشل → أزح المنصّة أو أضف واحدة وسطية.
هذه الدالة هي الفرق بين لعبة ممتعة ولعبة مكسورة. **لا تُهمَل.**

function buildYoussef(){

## 13. الصوت (WebAudio خالص — صفر ملفات)

```js
function blip(freq, dur, type='square', vol=0.12){
  const o = ac.createOscillator(), g = ac.createGain();
  o.type = type; o.frequency.setValueAtTime(freq, ac.currentTime);
  g.gain.setValueAtTime(vol, ac.currentTime);
  g.gain.exponentialRampToValueAtTime(0.001, ac.currentTime + dur);
  o.connect(g).connect(master); o.start(); o.stop(ac.currentTime + dur);
}
```
| الحدث | الصوت |
|---|---|
| قفز | `blip(520 → 780, 0.12, 'square')` مع انزلاق تردّد |
| عملة | نغمتان `988` ثم `1318` بفاصل 60ms |
| دوس عدو | ضوضاء بيضاء قصيرة + `blip(180, 0.1, 'sawtooth')` |
| ضرر | `blip(140 → 70, 0.35, 'sawtooth')` |
| قوّة | أربع نغمات صاعدة (أربيجيو) |
| موت | نزول كروماتيكي 8 نغمات |
| نهاية مرحلة | لحن انتصار 6 نغمات |

**الموسيقى:** مولّد بسيط — لكل عالم سلّم موسيقي (`pentatonic` عربي للعالم 1–2، `minor` للعوالم المظلمة)

## 17. الأداء (هدف ثابت 60fps)

1. **نافذة التفعيل** — فقط الكيانات ضمن `player.x ± 70` تُحدَّث وتُرسم. الباقي `visible = false`.
2. **InstancedMesh** — كل الكتل من نفس النوع في `InstancedMesh` واحد (مرحلة نموذجية: 800 كتلة → 6 نداءات رسم).
3. **تجميع الأشكال والمواد** — `BoxGeometry` واحد يُعاد استخدامه، `MeshLambertMaterial` (أرخص من Standard).
4. **الظلال** — ظلّ ديناميكي واحد فقط بخريطة `1024²` وصندوق ضيق يتبع اللاعب (`shadow.camera` = 40×40 وحدة).
   على الأجهزة الضعيفة: استبدل بـ **blob shadow** (دائرة شفافة تحت اللاعب).
5. **تجميع الكائنات (Pooling)** — 200 جسيم + 50 مقذوفاً مُعاد تدويرها. **صفر تخصيص في الحلقة.**
6. **كشف تلقائي للجودة** — قياس متوسط الإطار أول 3 ثوان → `low / medium / high`
   (تعطيل `antialias`، خفض `pixelRatio` إلى 1، إيقاف الظلال).
7. **رياضيات بلا قمامة** — متجهات مؤقتة معلنة خارج الدوال (`const _v = new THREE.Vector3()`).

# ملحق · ما تغيّر أثناء التنفيذ الفعلي

نُفِّذت اللعبة في `youssef-3d/index.html` واختُبرت آلياً في Chromium. هذه القرارات
تغيّرت عن المواصفات الأصلية، وكلّها نتيجة اختبار حقيقي لا تفضيل نظري:

| البند | المواصفات | ما استقرّ عليه التنفيذ | السبب |
|---|---|---|---|
| **تصحيح الحافة** | غير مذكور | أُضيف `LEDGE_SNAP = 0.55` | لاعب آلي فشل في ٢٧ من ٣١ مرحلة؛ السبب أن الهبوط على حافة منصّة يرتطم بجدارها. بإضافة التصحيح ارتفع الإكمال إلى ٢٩/٣١ فوراً. **أهم تغيير في المشروع.** |
| **خطّ النهاية** | جوهرة تُلتقط | خطّ يعبر عرض الممرّ | الجوهرة عند `z=0` كان يمكن تجاوزها بالجري في مسار جانبي |
| **نهاية الزعيم** | جوهرة تظهر بعد هزيمته | فوز تلقائي بعد ١٫٨ث | نفس السبب |
| **الماء (عالم ٦)** | سباحة بجاذبية ÷٣ | غرق قاتل | السباحة تحت المرحلة تُنتج قفلاً بلا مخرج |
| **الحمم الصاعدة** | ترتفع طوال المرحلة | محصورة بسقف، وفي عالم ٩ فقط | كانت تغرق مرحلة طولها ٦٠٠ وحدة بالكامل خلال ٥٥ ثانية |
| **العالم ٨** | ٢٥٪ من الأرض نطّاطة | رياح جانبية في الهواء | الأرض النطّاطة العشوائية تسلب التحكّم |
| **قصّ القفزة** | تضاؤل مستمر | ضربة واحدة عند الإفلات | التضاؤل المستمر جعل القفزة القصيرة عاجزة عن عبور أي فجوة |
| **عدد القطع** | ٤٥ | ٢٨ | كافية للتنويع؛ مع **حارس** يمنع تجاوز الطول المعلن (كان السبب الجذري لتداخل القطع وكسر الهندسة) |
| **حمل Three.js** | cdnjs | jsdelivr مع بديل unpkg ورسالة فشل عربية | مسار مثبّت على نسخة `three@0.160.1` مضمونة الوجود |

## درس التصميم الأهم

المدقّق الهندسي (لا فجوة > ٦٫٤، لا ارتفاع > ٢٫٥٥) كان **يمرّ ١٠٠٪ بينما اللعبة
غير قابلة للّعب**. الهندسة الصحيحة لا تكفي: احتاج الأمر لاعباً آلياً يلعب فعلاً
ليكشف أن المشكلة في *إحساس* التصادم لا في *أرقام* التصميم.
