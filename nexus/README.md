# NEXUS — منصة ألعاب مشتركة على Netlify + Firebase

هذا المجلد هو موقع NEXUS كاملًا (ملف `index.html` واحد) مع ملفات إعداد Firebase و Netlify.

| الملف | ما هو |
|---|---|
| `index.html` | NEXUS نفسه. **إعداد Firebase في أعلى الملف فقط** (ابحث عن `NEXUS_FIREBASE:BEGIN`). |
| `translations.js` | قاموس الواجهة: العربية · English · हिन्दी. ارفعه بجانب `index.html` — بدونه تبقى الواجهة بالعربية. |
| `firestore.rules` | قواعد Firestore: الألعاب العامة مقروءة للجميع، المشاريع للمالك فقط، العدادات تُفرض على الخادم. |
| `storage.rules` | قواعد Storage: الأصول الخاصة للمالك فقط، ملفات اللعبة تتبع خصوصية اللعبة، لا كتابة على مسارات الآخرين. |
| `firestore.indexes.json` | الفهارس التي تستعملها قوائم الألعاب والأصول والبحث. |
| `firebase.json` | لنشر القواعد والفهارس بأمر واحد، ولتشغيل المحاكيات محليًا. |
| `cors.json` | يسمح لموقعك بتنزيل ملفات Storage (المجسمات والأصوات) — بدونه لا تُحمَّل الأصول على الأجهزة الأخرى. |
| `_headers` / `netlify.toml` | إعداد Netlify: `index.html` لا يُخزَّن قديمًا، فيصل أي تحديث لكل الهواتف فورًا. |
| `lib/model-compress.js` | يصغّر ملفات ‎.glb الكبيرة قبل رفعها (يُحمَّل فقط عند الرفع). ارفعه مع المجلد. |
| `sw.js` | العمل بدون إنترنت: يحفظ NEXUS ومكتباته وملفات الألعاب التي فُتحت على الهاتف. ارفعه بجانب `index.html`. |
| `tests/` | الاختبارات: مجلس الذكاء (الخادم، الدالة السحابية، المتصفح)، المنصة (أيقونات الأصول، العمر، هاتف آخر، Pro، بلا مزوّد)، و sw.js — تُشغَّل بـ Node على حاسوب ولا يخدمها الموقع. |

## لماذا لم تظهر اللعبة على الهاتف الثاني؟

كان `NEXUS_FIREBASE` فارغًا، والنسخة القديمة كانت تبحث عن الإعداد في `/__/firebase/init.json` — وهذا المسار موجود فقط على Firebase Hosting وليس على Netlify. فكان كل هاتف يعمل في **LOCAL MODE** ويحفظ ألعابه في IndexedDB الخاص به فقط، ولا يوجد أي مصدر بيانات مشترك.

## خطوات التشغيل (مرة واحدة من صاحب المنصة)

1. **Firebase Console → Build → Authentication → Sign-in method**: فعّل **Anonymous** و **Email/Password** و **Google**.
2. **Firestore Database → Create database** (Production mode).
3. **Storage → Get started**. (المشاريع الجديدة تحتاج خطة **Blaze** لإنشاء حاوية Storage؛ الاستخدام الصغير يبقى ضمن الحصة المجانية. بدون Storage يعمل النشر، لكن لا يمكن رفع المجسمات والأغلفة.)
4. **Project settings → General → Your apps → Web app (</>)** → انسخ `firebaseConfig`.
5. ✅ **تم** — إعداد المشروع `jknbb-n` مضمّن في أعلى `index.html` داخل الكتلة (لتغييره لاحقًا عدّل نفس الكتلة):
   ```js
   /* NEXUS_FIREBASE:BEGIN */
   window.NEXUS_FIREBASE = { apiKey: "…", authDomain: "…", projectId: "…", storageBucket: "…", messagingSenderId: "…", appId: "…" };
   /* NEXUS_FIREBASE:END */
   ```
   أو من الهاتف: افتح NEXUS ← ⚙ الإعدادات ← **التشخيص** ← **إعداد Firebase للمالك** ← الصق الإعداد ← «اختبار» ← «تنزيل index.html مُعدّ».
   هذا الإعداد ليس سرًا (يعرّف المشروع فقط). لا تضع أبدًا مفتاح Service Account أو Admin SDK أو مفتاح AI هنا.
6. **انشر القواعد والفهارس** (من هذا المجلد، على حاسوب أو Cloud Shell):
   ```bash
   npm i -g firebase-tools
   firebase login
   firebase use jknbb-n
   firebase deploy --only firestore:rules,firestore:indexes,storage
   ```
   (عند نشر storage.rules سيطلب الإذن للقواعد المتقاطعة مع Firestore — وافق.)
7. **CORS لحاوية Storage**: عدّل `cors.json` وضع رابط موقعك بدل `https://YOUR-SITE.netlify.app`، ثم في Google Cloud Shell:
   ```bash
   gsutil cors set cors.json gs://jknbb-n.firebasestorage.app
   ```
8. **Authentication → Settings → Authorized domains**: أضف `YOUR-SITE.netlify.app` (مطلوب لتسجيل الدخول بـ Google).
9. **Netlify**: اسحب مجلد `nexus` كاملًا إلى Netlify Drop، أو اربط المستودع واجعل *Base directory* = `nexus`. الموقع يعمل عبر HTTPS تلقائيًا.

## تخزين الملفات على Google Drive (بدون خطة Blaze)

المجسمات وملفات MP3 والصور والأغلفة والفيديو تُرفع إلى **Google Drive الخاص بمن يرفعها**، داخل مجلد اسمه «NEXUS». كل ملف يُشارَك «لأي شخص لديه الرابط»، ويحفظ Firestore رابطه فقط. الإعداد في أعلى `index.html`: `window.NEXUS_FILES = "drive"` (أو `"firebase"` لاستعمال Firebase Storage).

- NEXUS يطلب صلاحية `drive.file` فقط: يرى الملفات التي أنشأها هو، ولا يرى بقية ملفات Drive.
- الرفع يحتاج تسجيل الدخول بـ Google. إذن Google يدوم ساعة، وبعدها تظهر نافذة Google عند الرفع التالي.
- إذا حذف صاحب الملف ملفه من Drive، يختفي من NEXUS.
- **الملف نفسه لا يُرفع مرتين:** لكل ملف بصمة (SHA-256). إذا كان الملف نفسه موجودًا في المكتبة العامة يُستعمل الموجود، وتظهر النسخ القديمة المكررة بطاقة واحدة في المكتبة. «أصولي» تعرض كل نسخك لتحذف ما تريد.
- **المجسمات الكبيرة تُصغَّر تلقائيًا:** ملفات ‎.glb الأكبر من 512 KB تُضغط قبل الرفع (هندسة meshopt، والصور الأكبر من 1024px تتحول إلى WebP). الشكل لا يتغير، والحجم يصغر عادة بين 50% و80%. إذا فشل الضغط يُرفع الملف الأصلي.

**الإعداد مرة واحدة (Google Cloud Console، المشروع `jknbb-n`، رقم المشروع 711797656698):**
1. APIs & Services ← Library ← **Google Drive API** ← **Enable**.
2. APIs & Services ← Credentials ← المفتاح الذي يبدأ بـ `AIzaSyDYrd1…`: إن كان «Restrict key» فأضف **Google Drive API** إلى القائمة ← Save.
3. OAuth consent screen / Google Auth Platform ← Audience ← **Publish app** (In production). بدون هذا لا يستطيع تسجيل الدخول إلا «مستخدمو الاختبار». `drive.file` صلاحية غير حساسة، فلا تحتاج مراجعة من Google.
4. Firebase ← Authentication ← Settings ← Authorized domains ← أضف نطاق Netlify.
5. افتح ⚙ ← التشخيص: يجب أن يظهر `Storage: Google Drive ✓`.

## أيقونات الأصول و«مسح الذاكرة المؤقتة» (لماذا كانت تختفي ثم تعود)

**ما كان يحدث:** Google Drive يرسل كل ملف بـ `cache-control: private, max-age=0, must-revalidate` وبلا ETag، فالمتصفح لا يحتفظ بأيقونة من Drive أبدًا — كل عرض للمكتبة كان يُنزّلها من Drive من جديد. النسخة الوحيدة على الجهاز كانت ذاكرة `sw.js` (للعمل دون إنترنت)، وكانت: (1) لا تُستعمل إلا إذا انقطعت الشبكة تمامًا، (2) تُكتب فوقها رفضات Drive (‏403 «حدّ التنزيل» / 429) لأن طلب `<img>` «معتم» لا يُرى رمزه، (3) تُمسح مع «مسح الذاكرة المؤقتة». وبطاقة الأصل كانت تطلب الأيقونة **مرة واحدة** بلا إعادة محاولة، فتبقى مربعًا فارغًا طوال الزيارة. لذلك: بعد المسح، أي رفض مؤقت من Drive أو شبكة ضعيفة = أيقونات فارغة، ثم «تعود وحدها» حين يقبل Drive من جديد — **لم يُحذف شيء أبدًا**: السجل في Firestore والملف في Drive بقيا كما هما. (جُرّب ذلك بـ `sw.js` الحقيقي في Chromium: `tests/sw-media.test.mjs` يفشل 6 من 8 مع النسخة القديمة.)

**الآن — ثلاث طبقات منفصلة:**
- **الدائم (الحقيقة الوحيدة):** سجل الأصل في Firestore ‏`assets/<id>` (`thumbnail` · `thumbnailURL` · `storagePath` · `downloadURL`) وملفاته في Drive / Storage. لا يمسّه أي «مسح» في الصفحة.
- **نسخة الأيقونة على هذا الجهاز (طبقة تسريع فقط):** قاعدة IndexedDB منفصلة اسمها `nexus-cache`. تُنزَّل الأيقونة مرة واحدة ثم تُعرض من هنا (أقل تنزيلات من Drive = أقل اصطدام بحدوده). حذفها لا يُفقد شيئًا: تُبنى من جديد من السجل.
- **المؤقت:** المجسمات في الذاكرة، ونسخ `sw.js` للعمل دون إنترنت (صارت `nexus-media-v2`: تُحفظ الملفات الحقيقية فقط، وتُعرض النسخة المحفوظة ما دام Drive يرفض أو الشبكة مقطوعة، والنسخة القديمة v1 تُحذف).

**إعادة البناء:** بطاقة الأصل تعرض رمز نوعه (🧊 🖼️ 🔊) حتى تصل الأيقونة — لا مربع فارغ — وتعيد المحاولة وحدها (3 ث، 12 ث، 45 ث، 3 د، وفورًا عند عودة الشبكة). وإذا حُذف ملف الأيقونة نفسه من Drive تُرسم أيقونة جديدة من ملف المجسم ذاته (وإن كنت صاحبه وإذن Drive معك تُصلَح في سجله أيضًا). ⚙ ← «مسح ذاكرة الأصول المؤقتة» يحذف النسخ فقط، ثم يعيد بناء أيقونات أصولك من Firebase فورًا.

## السرعة والعمل بدون إنترنت

- الزيارة الأولى تتصل بـ Firebase قبل الفتح. الزيارات التالية تفتح فورًا، والتحقق من الخادم يجري في الخلفية.
- بدون إنترنت: يفتح NEXUS من ذاكرة الهاتف، ومؤشر الحالة يقول «بلا إنترنت». الألعاب والمشاريع التي فُتحت مرة واحدة على الأقل بالإنترنت تعمل، والتعديلات تُرسل تلقائيًا عند عودة الاتصال. النشر ورفع الملفات يحتاجان إنترنت.
- عند رفع نسخة جديدة يصل `index.html` الجديد فورًا متى أجابت الشبكة خلال 3 ثوانٍ.

## التحقق من أن الهاتفين على نفس المشروع

افتح الموقع على كل هاتف ← ⚙ ← **التشخيص**. يجب أن يظهر في الهاتفين:

- `Firebase: CONNECTED` و `Mode: FIREBASE`
- نفس `Firebase Project`
- `Games (زائر آخر): READABLE` — هذا فحص حقيقي بجلسة غير مسجّلة، أي ما يراه هاتف آخر
- `آخر لعبة لك: ✓ الزائر يقرأ السجل والنسخة القابلة للتشغيل`
- `Storage: AVAILABLE` و `Storage CORS: OK`

مؤشر الحالة أعلى الشاشة: **Online** (أخضر) = بيانات مشتركة · **Local Mode** (برتقالي) = لا يوجد إعداد، هذا الجهاز فقط · **Firebase Error** (أحمر) = يوجد إعداد لكن الاتصال فشل (السبب الحقيقي داخل المؤشر).

## اختبار الهاتفين (النهائي)

1. الهاتف A: افتح الرابط ← الحساب ← تسجيل الدخول ← أنشئ لعبة باسم `TEST NEXUS SHARED GAME` ← نشر ← عام.
   تظهر نافذة «تم النشر» فقط بعد أن يُقرأ السجل من الخادم نفسه.
2. الهاتف B: افتح نفس الرابط ← سجّل بحساب آخر ← الرئيسية أو المجتمع ← ألعاب ← ابحث عن الاسم ← افتح ← تشغيل.

## اختبار محلي بمحاكيات Firebase (بدون مشروع حقيقي)

```bash
cd nexus
firebase emulators:start --project demo-nexus --only auth,firestore,storage
python3 -m http.server 8000          # في نافذة أخرى
# ثم افتح: http://localhost:8000/index.html?emulators=1  (في متصفحين مختلفين = هاتفان)
```

## أوامر المساعد (تنفَّذ فعليًا على المشروع، بمزوّد AI أو بدونه)

- «أضف سيارة رياضية قرب المبنى» · «اجعلها أكبر» · «ضعها خلف المنزل» · «لف السيارة 90 درجة»
- «استبدل السيارة بسيارة أخرى من أصولي» · «ابحث في المكتبة العامة عن شجرة» · «ضع ثلاث سيارات أمام المبنى»
- «ضع الأشجار حول المنطقة» (يسأل عن العدد ويعرض معاينة قبل التطبيق) · «احذف السيارة» · «انسخ السيارة»
- «ماذا يوجد في المشهد؟» · «حلل لعبتي» · «أصلح الخطأ الموجود في الكود» · «ما حالة اللعبة الآن؟» · «تراجع»
- بمزوّد AI متصل: «اجعل الباب يفتح عند الاقتراب» → تعديل كود مع عرض الفرق قبل التطبيق.

الاتجاهات (أمام/خلف/يمين/يسار) تُحسب من زاوية الكاميرا الحالية كما تراها على الشاشة.

## بناء لعبة من ملفاتك (AI Game Builder)

- مثال: «اصنع لي لعبة قيادة صغيرة. ضع الطريق في المنتصف، المنازل على الجانبين، الأشجار حول الطريق، والسيارة في نقطة البداية.»
- يبحث في ملفات المشروع وملفاتك أولًا ثم المكتبة العامة (مع اسم صاحب الأصل)، ويعرض معاينة بالملفات المختارة قبل التطبيق.
- «✓ استخدم أصول مشروعي» في لوحة المساعد: إطفاؤه يمنع استعمال ملفاتك. «ما الذي يراه؟» يعرض الملفات التي يستطيع استعمالها.
- البناء كله خطوة تراجع واحدة: «تراجع» ثم «أعد». يُكتب DrivingController.js ويُجرى تشغيل تجريبي ويُحفظ المشروع.
- نوع كل ملف (مركبة، مبنى، طريق، شجرة، شخصية…) يُستنتج من اسمه وأسماء أجزائه ووجود هيكل عظمي وأبعاده — ليس تحليلًا بصريًا.
- النموذج المتصل (إن وُجد) يرى بيانات الملفات فقط (الاسم والنوع والأبعاد)، لا الملفات ولا الروابط ولا المفاتيح، وأوامره محصورة في عمليات محددة يتحقق منها NEXUS.

## ربط نموذج ذكاء اصطناعي (Groq / Grok / OpenAI …)

- ⚙ في المساعد ← الصق المفتاح فقط. NEXUS يعرف المزوّد من بداية المفتاح (Groq `gsk_` · xAI Grok `xai-` · OpenAI `sk-` · Anthropic `sk-ant-` · Gemini `AIza` · OpenRouter `sk-or-`)، ويختار نموذجًا موجودًا فعلًا من قائمة المزوّد، ويختبر الاتصال، ثم يفعّله.
- التحية والأسئلة تُجاب كمحادثة ولا تتحول إلى بناء أو كود. بدون نموذج يرد المساعد ردًا قصيرًا صادقًا ويعرض ما يستطيعه.
- مع نموذج متصل: المحادثة ترى بيانات ملفاتك (A1، A2… بالنوع والأبعاد، دون روابط أو معرّفات أو مفاتيح) وكائنات المشهد وأسماء ملفات الكود، وتستطيع اقتراح تعديلات (إضافة ملفاتك، أشكال، تحريك، حذف، سكربتات، بناء لعبة كاملة). كل تعديل يُفحص ويُعرض قبل التطبيق، ويُطبَّق كخطوة تراجع واحدة.
- إذا أوقف المزوّد نموذجًا أو تجاوز الطلب حدّ الرموز في الدقيقة (Groq المجاني) يعيد NEXUS المحاولة تلقائيًا بنموذج موجود أو برد أقصر.
- **مواقع الوسطاء (Resellers) مثل cleanapis وأي API متوافق مع OpenAI:** «مزوّد مخصّص» ← Base URL + المفتاح + النموذج. نماذج gpt-5/o-series/thinking/r1 تُرسَل بـ`max_completion_tokens` مع مساحة للتفكير و`reasoning_effort: low` وبلا `temperature`؛ وما يرفضه موقع ما (400) يتعلّمه NEXUS مرة واحدة ويُعيد الطلب صحيحًا. نموذج «يفكّر» باسم غير معروف يرد فارغًا حين يصرف ميزانيته في التفكير: يُعاد مرة واحدة بمساحة أكبر ويُحفظ ذلك له (الطلب التالي طلب واحد)، وإن بقي فارغًا تظهر رسالة واضحة بدل جواب فارغ يأكل الرموز.
- **«استخدم نماذجي» / «use my models» / «मेरे मॉडल इस्तेमाल करो»** في المساعد أو المحادثة: يتحوّل فورًا إلى نموذجك (دون سؤال أي نموذج ودون رموز)، ومجلس الذكاء يبقى على نماذجك وحدها؛ و«استخدم NEXUS AI» يعيد الذكاء المجاني. في Smart Council مع نموذجك الخاص يجيب نموذجك وحده.
- **🕹 ألعاب ثنائية الأبعاد:** «اصنع لعبة ثنائية الأبعاد عن…» (أو 2D game / 2D गेम) ← يكتب النموذج المتصل لعبة HTML5 كاملة في ملف واحد (canvas، لمس + لوحة مفاتيح + فأرة، شاشة بداية ونهاية، نقاط، أصوات WebAudio، بلا روابط خارجية)، يُفحص كودها (وإصلاح واحد إن لم يُترجَم)، وتُحفظ في «تطبيقاتي» خاصة بك مع زر ▶ للعب.

## صفحة عرض اللعبة (Game Showcase) ووسائط اللعبة (GAME MEDIA)

- رابط اللعبة يفتح أولًا صفحة العرض: الخلفية، الغلاف، الاسم، الوصف المختصر، المطوّر، التصنيف، الوسوم، ثم PLAY GAME و WATCH GAMEPLAY، وأقسام فيديو اللعب واللقطات والوصف والمعلومات، ثم مشاركة ومفضلة وإبلاغ. بعد الخروج من اللعبة يعود اللاعب إلى الصفحة.
- «وسائط اللعبة · GAME MEDIA» (من «لوحة المشروع» أو القائمة ⋯ أو نافذة النشر): الغلاف، الصورة المصغّرة، البانر، خلفية الصفحة (مع قوة الظل)، فيديو اللعب، حتى 12 لقطة، وترتيب اللقطات والأقسام، ومعاينة الصفحة.
- الملفات تُرفع إلى نفس تخزين المشروع (Google Drive أو Firebase Storage) مع عرض الحجم قبل الرفع وشريط تقدّم. الصور تُضغط إلى WebP بحجم مناسب، وللفيديو صورة معاينة. المراجع تُحفظ في المشروع وفي سجل اللعبة المنشورة، فتظهر نفسها على كل الأجهزة، وأي تغيير بعد النشر يظهر فورًا.
- رابط المشاركة على Netlify: `https://موقعك.netlify.app/game/<gameId>` (القاعدة في netlify.toml). على استضافة أخرى يُستعمل `…/#game/<gameId>`.
- **التعديل من صفحة اللعبة نفسها:** صاحب اللعبة يرى في صفحتها زر «✎ تعديل الصفحة · EDIT» بجانب PLAY، وكل مكان فارغ يقول ما يوضع فيه: «＋ أضف غلافًا»، «＋ أضف جملة تعريفية»، «＋ أضف فيديو للعبة»، «＋ أضف صورًا من لعبتك»، «＋ اكتب شرحًا للعبة». الضغط يفتح «وسائط اللعبة» عند ذلك المكان مباشرة، والإغلاق يعيدك إلى الصفحة محدّثة.
- **لماذا لا أرى «تعديل الصفحة» وأرى «+ متابعة»؟** لأن الحساب المفتوح ليس الحساب الذي نشر اللعبة. أكثر سبب: النشر تمّ في «جلسة ضيف» (اسم المطوّر يكون مثل `creator_Etro4`) ثم سجّلت الدخول بحساب آخر. الآن:
  - قبل النشر كضيف يسألك NEXUS «تنشر وأنت ضيف؟» ويقترح تسجيل الدخول أولًا.
  - وإذا سجّلت الدخول لاحقًا **من المتصفح نفسه** الذي نشرت منه، تنتقل ألعابك المنشورة إلى حسابك وحدها (نفس الصفحة ونفس الرابط)، ثم تعدّلها من أي جهاز. النقل محمي بقواعد Firestore بسرّ لمرة واحدة لا يعرفه إلا ذلك المتصفح.
  - لعبة نُشرت كضيف في متصفح لم يعد فيه ذلك الضيف لا يمكن نقلها من التطبيق (لا أحد يملك تلك الجلسة). حلّان: انشرها من جديد من «مشاريعي» (نسخة المشروع نُقلت إلى حسابك)، أو من Firebase Console ← Firestore ← games ← (اللعبة) غيّر `ownerId` إلى معرّف حسابك (User UID — تجده في Firebase Console ← Authentication بجانب بريدك)، وغيّر `ownerId` في builds ← (نفس المعرّف) أيضًا.
- صاحب اللعبة وحده يعدّل الوسائط (قواعد Firestore و Storage)؛ الزائر يشاهد ويلعب فقط. في وضع Firebase Storage انشر storage.rules الجديد (`firebase deploy --only storage`) ليُسمح برفع الفيديو حتى 128 MB.

## الذكاء الاصطناعي المجاني المدمج (مفاتيح صاحب المنصة على الخادم)

(لعرض كل نماذج Google التي تتيحها مفاتيحك ضع `GEMINI_ALL_MODELS=1`.) نموذج نفد حدّه لا يوقف المفتاح عن النماذج الأخرى. النموذج الذي تختاره هو الذي يجيب (يظهر اسمه تحت كل رد)، و«auto» يختار الأنسب ويتنقّل وحده عند انتهاء الحدّ. مفاتيحك الخاصة (إن أضفتها من ⚙) تظهر في القائمة نفسها.

  Site configuration ← Environment variables ← Add a variable:
  - `GEMINI_KEYS` = مفاتيح Google AI Studio مفصولة بفاصلة
  - `GROQ_KEYS` = مفاتيح Groq مفصولة بفاصلة
  - `OPENROUTER_KEYS` = مفاتيح OpenRouter مفصولة بفاصلة (تُستعمل نماذج OpenRouter المجانية فقط، ولا يُصرف أي رصيد)

  - اختياري: `GEMINI_MODELS` (الافتراضي gemini-3.6-flash)، `GEMINI_ALL_MODELS=1`، `GROQ_MODELS` / `OPENROUTER_MODELS` / `ANTHROPIC_MODELS` (قائمة ثابتة بدل قائمة المزوّد)، `GEMINI_BASE` / `GROQ_BASE` / `OPENROUTER_BASE` / `ANTHROPIC_BASE` (عنوان آخر لنفس الـAPI)، `AI_PER_MINUTE` (الافتراضي 20 طلبًا في الدقيقة لكل لاعب)
  - بعد إضافة المتغيّرات أو تغييرها: Deploys ← Trigger deploy (الدالة تقرأ القيم الجديدة في النشر التالي).
- إذا ظهر «الذكاء المجاني غير مفعّل» يقول NEXUS السبب بالضبط: «الموقع رُفع بالسحب والإفلات — الدوال لا تعمل» أو «الدالة تعمل لكن بلا مفاتيح».

  Site configuration ← Build & deploy ← Link repository ← اختر المستودع، ثم Base directory = `nexus`، واختر الفرع.

## 🔑 مفاتيح الذكاء المجاني — صندوق صاحب الموقع (بدون لمس Netlify كل مرة)
- الإعدادات ← «🔑 مفاتيح الذكاء المجاني — لصاحب الموقع» (أو من بطاقة NEXUS AI، أو من «اختر النموذج»): الصق مفاتيح Gemini أو Groq أو OpenRouter (كل مفتاح في سطر) ثم «حفظ على الخادم».
- الخادم يجرّب كل مفتاح أولًا: المرفوض لا يُحفظ، والذي وصل حدّه يُحفظ ويُستعمل عندما يتجدّد. تُحفظ في Firestore `platformSecrets/ai` — مستند لا يستطيع أي متصفح قراءته (قواعد firestore.rules)، ولا يعود أي مفتاح إلى أي صفحة، ولا حتى إليك (تظهر «Groq ••••a1b2» فقط).
- كل من ليس عنده مفتاح يحصل على الذكاء المجاني ويختار النموذج فقط؛ إذا انتهى حدّ مفتاح يُستعمل التالي، ثم المزوّد الآخر، ثم «غير متاح الآن». مفاتيح الصندوق تُضاف إلى مفاتيح `GEMINI_KEYS` / `GROQ_KEYS` إن وُجدت.
- **صاحب الصندوق:** أول حساب Google يحفظ مفتاحًا (بعدها لا يستطيع غيره الإضافة أو الحذف)، أو من تضع بريده في `ADMIN_EMAILS` في Netlify.
- **أين تُحفظ:** في مخزن موقعك نفسه على Netlify (Netlify Blobs) — يعمل وحده على أي موقع Netlify مربوط بـ GitHub، بلا أي متغيّر ولا إعداد. (الدوال لا تعمل بالسحب والإفلات.) على استضافة أخرى: `FIREBASE_SERVICE_ACCOUNT` = محتوى ملف JSON من Firebase Console ← Project settings ← Service accounts ← Generate new private key، ثم Trigger deploy. الصندوق نفسه يشرح لك ما ينقص بالضبط: «الخادم لا يرى المتغيّر (أعد النشر بعد إضافته، وتأكّد أن Scopes يشمل Functions)» · «القيمة ليست محتوى ملف JSON» · «المحتوى ناقص» · «Google رفض حساب الخدمة (مع سبب Google)» · «Firestore رفض». يُقبل محتوى الملف كما هو، أو بأسطر مكسورة من نسخ الهاتف، أو بين علامتي تنصيص، أو base64، أو متغيّران `FIREBASE_CLIENT_EMAIL` و `FIREBASE_PRIVATE_KEY`.
- إلى أن يعمل الصندوق: الصق مفاتيحك فيه واضغط «جهّز نصًّا جاهزًا للصقه في Netlify» — يصنع على جهازك نصًّا واحدًا (`GEMINI_KEYS=…` و `GROQ_KEYS=…`) تلصقه في Environment variables ← Import from a .env file، ثم Trigger deploy؛ فيعمل الذكاء المجاني فورًا بمفاتيحك دون أن يراها أحد.

## 🤝 مجمّع مفاتيح اللاعبين (API Key Pool)
- الإعدادات ← «🤝 تبرّع بمفتاح للذكاء المجاني» (لأي لاعب مسجّل بحساب): الصق مفتاح Gemini أو Groq أو OpenRouter أو Claude (`sk-ant-…` — مدفوع، والنافذة تقول ذلك للمتبرّع)، وافق، ثم «تبرّع بالمفتاح». يُكتب مرة واحدة في Firestore `api_keys`، و**لا يستطيع أي متصفح قراءته بعد ذلك** (`allow read: if false`) — ولا حتى أنت؛ ترى فقط «Groq ••••a1b2 — 🟢 يعمل» وزر «سحب».
- يستعمله الخادم فقط: الدالة السحابية `processRequest` (المجلد `functions/` — تحتاج خطة Blaze) أو خادم الذكاء في الموقع على Netlify إذا وُضع `FIREBASE_SERVICE_ACCOUNT`. يُختار مفتاح عشوائي، والمفتاح المرفوض (401) يُعطَّل، والذي وصل حدّه (429) يرتاح ثم يعود، ويُجرَّب غيره تلقائيًا.
- **مفتاح أي موقع متوافق مع OpenAI** (وسيط مثل cleanapis): اكتب Base URL الموقع مع المفتاح (والنموذج إن لم يعطِ الموقع قائمة). الخادم وحده يفحص العنوان (https عام فقط، لا عناوين داخلية)، ويجلب `/models`، ويختبر المفتاح **بطلب حقيقي**، ثم يحفظه في `api_keys` (لا يعود لأي متصفح). يمكنك التبرّع بعدة مفاتيح (حتى 5 خانات) وسحبها متى شئت.
- **💎 متبرّع قوي:** إن كان مفتاحك يعمل بنموذج قوي (GPT-4o/4.1/5، Claude، Gemini Pro/Flash، Grok 3/4، Llama 70B+، DeepSeek V3/R1، Qwen 72B+ …) يحفظ الخادم `donors/<uid>` بدرجة `strong`: شارة «💎 متبرّع قوي» في ملفك، و**نقاط الإعلانات ×2** (الخادم `points.js` يتحقق عند كل إعلان أن مفتاحًا قويًا لك ما زال نشطًا). موقع ضعيف أو نماذج صغيرة ← «🤝 متبرّع» فقط، بلا ×2. المفتاح الذي يُعطَّل (401) يُسقط الدرجة تلقائيًا.
- **أي موقع — اختر بنفسك:** في نافذة التبرّع زرّان: «مزوّد معروف» (Gemini · Groq · OpenRouter · Claude) أو «أي موقع (Base URL)»: الصق رابط الموقع (ينتهي بـ `/v1` — يُصحَّح وحده: https وإضافة /v1) واسم النموذج إن لم يعطِ الموقع قائمة. مفتاح لا يشبه أي مزوّد معروف يفتح «أي موقع» وحده. **وإن لم تكن دوال الخادم تعمل** (رفع بالسحب والإفلات): يُحفظ المفتاح في المجمّع مباشرة بقواعد Firestore (`api_keys` بـ `base` و`models`) ويختبره الخادم لاحقًا — موقع يفشل اختباره لا يُستعمل أبدًا ويُعاد اختباره عند الطلب.
- الشرح الكامل والنشر: `functions/README.md`. **تنبيه صادق:** صاحب مشروع Firebase يستطيع رؤية المفاتيح من لوحة Firebase، وبعض المزوّدين قد تمنع شروطهم مشاركة المفاتيح — النافذة تقول ذلك للمتبرّع.

## 🧠 مجلس الذكاء · Multi-AI Council (NEXUS Pro)
حتى 4 نماذج ذكاء اصطناعي تعمل على المهمة الواحدة، كلٌّ بدوره، ثم يراجع أحدها كل النتائج ويكتب **نتيجة نهائية واحدة**. هذا **تعاون بين نماذج موجودة (Multi-AI collaboration)** — ليس نموذجًا جديدًا مُدرَّبًا ولا «أقوى من Claude».

```
طلب اللاعب ← AIClient (نفس المنسّق الموجود في PART 16 — لا منسّق ثانٍ)
          ← /api/ai/council (خادم الموقع: يقرأ Pro، يفرض الحدود، يدوّر المفاتيح)
          ← أعضاء بأدوار: المسودة الرئيسية ★ · الخطة · الأصول الحقيقية · المراجعة
          ← المراجعة والدمج (Review / Synthesis) ← نتيجة واحدة
          ← نفس المنفّذات: معاينة ← APPLY ← تراجع بخطوة واحدة
```

- **الأوضاع** — داخل لوحة المساعد نفسها «🧠 AI MODE» (○ Single AI ○ Smart Council ○ Full Council، وفي Full قائمة بالنماذج الحقيقية بمربعات اختيار، Maximum: 4)، وأيضًا 🧠 بجانب شارة النموذج أو «اختر النموذج» ← «اختر نماذج المجلس»:
  - **Single AI** — نموذج واحد لكل مهمة.
  - **Smart Council** (الافتراضي لـ Pro) — NEXUS يحلّل المهمة قبل تشغيل أي نموذج، **من عوامل لا من طول النص وحده**: حجم المطلوب · عدد العمليات · عدد الملفات التي تتغيّر · لعبة / مدينة / عالم كامل · Game Builder · بحث الأصول (Asset Search) · أنظمة اللعب (أعداء، مهام، مخزون، حفظ…) · كود ومنطق · أخطاء تحتاج تحليلًا · تعديل مشروع موجود · مراجعة واختبار — والتعديل الصغير الواحد (لون، اسم، حجم) يُنقص. مثال: «غير لون الزر إلى أزرق» → نموذج واحد · «أضف نظام حفظ للعبة» → نموذج أو اثنان · «أضف عدوًا يطارد اللاعب مع شريط صحة ونظام نقاط» → 2–3 · «ابنِ مدينة كاملة، استخدم Assets، أضف NPCs وسيارات وطرق ونظام مهام» → 4. لوحة التقدّم تقول «لماذا 3؟» بالأسباب ونقاطها. النقاط والعتبات من الخادم: `COUNCIL_SMART_THRESHOLDS` و `COUNCIL_SMART_WEIGHTS` (الجدول أدناه).
  - **Full Council** — حتى 4 نماذج في كل مهمة (إصلاح الأخطاء المتكرّر في حلقة البناء: نموذجان كحدّ أقصى).
- **اختيار النماذج:** حتى 4 من القوائم الحقيقية فقط (نماذج خادم الموقع كما يعيدها كل مزوّد، ونماذج مفاتيحك الخاصة). الأول يكتب المسودة الرئيسية. بلا اختيار: النموذج الذي تستعمله يقود و«NEXUS · auto» للبقية (يوزّعها الخادم على مزوّدين مختلفين). نموذج لم يعد موجودًا يُستبدل ويُقال ذلك. نماذج مفاتيحك الخاصة تعمل من متصفحك (مفاتيحك لا تصل إلى الخادم)، والدمج على الخادم.
- **الأدوار لا تكرّر العمل:** كل عضو يرى نفس السياق ويعمل من زاوية مختلفة — المسودة الكاملة، الخطة، الأصول، المراجعة (المراجع يبدأ بعد المسودة والخطة ويراجعهما فعلًا). نموذج الدمج **يبني على المسودة** ولا يكتب من الصفر.
- **الأصول الحقيقية:** في «بناء» (Game Builder) يبحث NEXUS بـ `Assets.search` — ملفاتك أولًا ثم المكتبة العامة — عن كل ما يذكره الطلب (طريق، مبانٍ، أشجار، سيارة، شخصيات…)، ويعطي المجلس هذه الأصول بمعرّفاتها الحقيقية. خطة المجلس تستطيع خطوة `compose` يضع فيها **GameComposer** الأصول بأحجامها الحقيقية (الطريق في المنتصف، المنازل على الجانبين، الأشجار حولها، السيارة في البداية)، ثم يكتب الكود، ثم البناء والتشغيل التجريبي والإصلاح. **أي assetId غير موجود يُرفض** (يُفحص قبل الوضع) ويُبحث عن أصل حقيقي بدلًا منه.
- **يعمل في كل مسارات المساعد:** المحادثة (بما فيها أوامر Editor Agent على العنصر المحدد: `ADD_SYSTEM` · `SET_COMPONENT` …)، الباني، وكيل الكود (فرق قبل التطبيق)، ومُصلح الأخطاء. النتيجة النهائية بنفس صيغة نتيجة نموذج واحد، فتمرّ بنفس الفحوص وتُنفَّذ فعلًا.
- **الشفافية:** أثناء العمل: كل نموذج «يفكّر · اكتمل · يعيد المحاولة (والسبب) · فشل»، ثم «المراجعة والدمج»، ثم «✓ Final result ready». تحت الرد نتيجة واحدة فقط، و«🧠 AI Council Details» يفتح مساهمة كل نموذج عند الطلب. لا يظهر أي مفتاح أبدًا.
- **الفشل:** إذا فشل نموذج يكمل الباقون بنتائجهم (يُحاول بمفتاح آخر ثم مزوّد آخر أولًا). إذا فشل نموذج الدمج يكمله نموذج آخر من المجلس. إذا فشل الدمج كليًا تُستعمل المسودة الرئيسية (ويُقال ذلك). إذا تعذّر المجلس كله يجيب نموذج واحد.
- **Pro على الخادم، لا في الصفحة:** الخادم يقرأ `wallets/<uid>.proUntil` (لا يكتبه إلا الخادم — firestore.rules) في كل طلب. **الحساب المجاني = نموذج واحد**: طلب مجلس بأكثر من نموذج من حساب مجاني يُرفض من الخادم (`403 pro_required`، لا يعمل أي نموذج ولا يُحسب شيء) مهما أرسلت الصفحة — تعديل JavaScript أو localStorage / sessionStorage أو الطلب نفسه من DevTools — ثم تجيب الصفحة بنموذج واحد وتقول السبب. والمتصفح لا يستطيع تغيير الاشتراك ولا العدّاد ولا الحدود، ولا رفع maxModels (Pro يرسل 8 → يعمل 4). بدون `FIREBASE_SERVICE_ACCOUNT` لا يستطيع الخادم التحقق من Pro، فيعمل نموذج واحد للجميع.
- **التكلفة:** كل استدعاء نموذج يُحسب طلبًا من طلبات ذكاء اليوم (`PRO_AI_PER_DAY`)، وما لم يُستعمل أو لم يُجب يُعاد. إن لم يبقَ ما يكفي يُصغَّر المجلس. مجلس واحد في كل مرة لكل حساب.
- **حدود الخادم** (Netlify ← Environment variables، تظهر للاعب ولا يغيّرها):

## 🏆 NEXUS CHALLENGES — تحديات يبتكرها NEXUS AI واحدًا بعد الآخر، ويحكم عليها NEXUS AI JUDGE
```
لا تحدٍّ الآن ← «NEXUS AI يبتكر التحدي التالي…»
  ← NEXUS AI يبتكر فكرة: القصة (اختيارية) والهدف والقواعد والميكانيكيات وطريقة الفوز والمعايير والمدة والجائزة المقترحة
  ← فحص الخادم: تكرار لتحدٍّ سابق بكلمات أخرى؟ ترند بلا بيانات؟ محتوى لا يناسب كل الأعمار؟
  ← مراجع AI (ثلاثة على مزوّدين مختلفين لفكرة معقدة): تكرار؟ ممكن في NEXUS؟ جودة؟ مدة واقعية؟
  ← قُبلت: تُنشر — أو فكرة أخرى (حتى 5)، ثم أفضل فكرة صالحة بدل توقف النظام
الصفحة الرئيسية «🏆 NEXUS CHALLENGES» ← «شارك في التحدي» (حسابك في Firebase — uid)
  ← تصنع لعبتك في محرر NEXUS نفسه (المساعد والأصول كالمعتاد — لا محرر جديد)
  ← المزيد ← «🏆 تسليم اللعبة للتحدي» (أي تحدٍّ؟ العام أو تحدي أصدقائك) = «نشر» NEXUS نفسه + تشغيل تجريبي لثانيتين
  ← /api/challenges/submit — الخادم يتحقق من الحساب واللعبة المنشورة والمشروع والوقت
  ← NEXUS AI JUDGE بمعايير هذا التحدي (مزوّدو ai.js ومفاتيحه وتدويرها) ← درجة من 100 ← /10
  ← نهاية الوقت: إغلاق التسليم ← تحكيم ما بقي ← ترتيب ← الفائز والوصيف ← نقاط (points.js) ← NEXUS AI يبتكر التالي
```
- **لا قائمة تحديات في أي مكان:** لا `const challenges = [...]` ولا اختيار عشوائي من قائمة — `challenges.js` يسأل «NEXUS Challenge Creator» عبر `ai.js` نفسه (المزوّدون، مجمّع المفاتيح، تدويرها وراحة المفتاح المرفوض؛ `CHALLENGE_GEN_MODELS` لتحديد النماذج). في الطلب: ما يستطيع NEXUS بناءه، التحديات السابقة (آخر 40 — «لا تكرّر ولا تغيّر الاسم أو المكان أو الوقت فقط»)، بيانات الترند إن وُجدت، طلب صاحب الموقع إن وُجد، الأفكار المرفوضة في هذه الجولة، و«بذرة تنوّع» (العشوائية للتنوّع فقط). الفكرة قد تكون عادية أو غريبة أو مضحكة أو غامضة أو قصصية، مزيجًا أو لا — والمطلوب قد يكون لعبة كاملة أو نموذجًا أوليًا أو تجربة أو ميكانيكية أو مستوى أو قتالًا أو فيزياء أو لغزًا أو عالمًا أو تجربة جماعية أو سلوك NPC أو محاكاة أو تجربة إبداعية.
- **لا صعوبات:** لا سهل/متوسط/صعب/خبير. يقدّر AI داخليًا `complexity.score` (1–10) و`estimatedBuildMinutes` و`gameplayComplexity` — يحدّد التعقيد عدد المحكّمين (1، واثنان من 7، وثلاثة من 9) والمراجعين (ثلاثة من 8)، فلا يُستدعى أكثر من نموذج إلا حين يستحق (التكلفة).
- **التكرار — طبقتان:** بصمة الخادم (كلمات العنوان والفكرة والميكانيكيات والكلمات المفتاحية بالعربية والإنجليزية، بلا الكلمات المشتركة، مع تجذيع خفيف) — تشابه 50% فأكثر يُرفض دون أي استدعاء AI؛ ثم المراجع يحكم على المعنى («سباق سيارات في مدينة ليلًا» = «سباق سيارات في مدينة»).
- **الجولة (MAX_GENERATION_ATTEMPTS = 5):** كل فكرة: ابتكار ← فحص ← مراجعة ← قبول أو رفض مع السبب. الجولة محفوظة في `challenges_meta/gen` (طلب انقطع أو انتهى وقته يكمله التالي). بعد 5 أفكار بلا قبول: تُنشر أفضل فكرة صالحة (`generation.fallback`). إن لم يُجب أي نموذج: لا يُخترع تحدٍّ بدونه — إعادة بعد 2 · 5 · 15 · 30 · 60 دقيقة، والصفحة تقول ذلك وتعرض الأفكار التي جُرّبت ولماذا رُفضت.
- **يُبتكر عند الحاجة:** تحدٍّ واحد مفتوح في كل وقت — لا آلاف مسبقًا. ينتهي ← يُبتكر التالي (أول زيارة بحساب، أو الدالة المجدولة كل 15 دقيقة بـ 24 ثانية تكفي فكرة ومراجعتها). صاحب الموقع يستطيع توجيه الفكرة التالية («شيء عن المطر») أو ابتكارها الآن — وAI هو من يبتكرها.
- **ما يقرّره AI:** العنوان، الرمز، السطر التعريفي، الوصف، القصة (اختيارية)، الفكرة، نوع المطلوب، الهدف، القواعد، الميكانيكيات، طريقة الفوز، المدة (ضمن 0.5–168 ساعة)، الجائزة المقترحة (ضمن 200–10000)، 3–7 معايير بأوزان مجموعها 100 (أحدها مطابقة التحدي — يضيفه الخادم إن غاب)، كلمات مفتاحية (للأدلة)، والإلهام: أصلية · بأسلوب لعبة معروفة (`gameReference` — الأسلوب فقط، لا أسماء ولا رسوم) · من ترند · مزيج.
- **الترندات:** فقط إن وضع صاحب الموقع رابط أخبار ألعاب (`CHALLENGE_TRENDS_URL`: RSS / Atom / JSON — يُقرأ كل 6 ساعات على الأكثر ويُحفظ في `challenges_meta/trends`) أو ملاحظاته. دونها يُقال لـ AI «لا بيانات ترند» ولا يُنشر تحدٍّ يدّعي ترندًا؛ وإن استُعمل خبر تظهر في صفحة التحدي سطوره ورابطه ومصدره — لا معلومات مخترعة.
- **كل القرار على الخادم** (`netlify/edge-functions/challenges.js`)؛ الصفحة (PART 37 في index.html) تعرض فقط. في Firestore: `challenges/<id>` (challengeId، seq، title، description، story، concept، gameReference، mechanics، objective، rules، duration، reward، judgingCriteria، createdAt، البصمة، التعقيد، generation، العدّادات، الفائز والوصيف والمراكز) · `challengeEntries/<challengeId>_<uid>` · `challengeRewards/<entryId>` (علامة «دُفعت») · `challenges_meta/config` و`state` و`gen` و`trends` · `friendChallenges` و`friendDrafts` و`friendUsage`. firestore.rules: **لا كتابة من أي متصفح** على أيٍّ منها، واللاعب يقرأ مشاركته هو فقط.
- **الدورة:** مفتوح حتى endTime (بساعة الخادم — العدّاد في الصفحة يتبعها حتى لو كانت ساعة الجهاز خاطئة) ← «التحكيم جارٍ» ← «أُعلنت النتائج». لا حاجة لخادم دائم: كل زيارة بحساب تحرّك ما حان وقته (بحدٍّ للموقع كله)، والدالة المجدولة `netlify/functions/challenges-tick.mjs` (كل 15 دقيقة) تعمل إن وُضع `CHALLENGES_CRON_SECRET`.
- **التسليم بلا تلاعب:** الصفحة ترسل ثلاثة معرّفات فقط (التحدي، المشروع، اللعبة) والتشغيل التجريبي. الخادم يتحقق: الحساب من توكن Firebase · `games/<id>` ملك الحساب ومن هذا المشروع وليست خاصة · `projects/<id>` ملك الحساب · `builds/<id>` نُشرت بعد بداية التحدي **بساعة قاعدة البيانات** (updateTime) · الوقت لم ينتهِ · لاعب في التحدي (لتحدي الأصدقاء). وقت التسليم يكتبه الخادم. أي «score» أو «rank» أو «winner» أو «reward» ترسله الصفحة يُتجاهل.
- **NEXUS AI JUDGE — معايير هذا التحدي لا «أعجبتني»:** الخادم يقرأ نسخة اللعبة المنشورة نفسها: المشهد، السكربتات (فحص صياغة كما يشغّلها NEXUS، المدخلات، حلقة اللعب، الهدف، فوز/خسارة/إعادة، الواجهة، الصوت، الفيزياء، العمل الثقيل في update)، الأصول، كلمات التحدي، وصفحة المتجر — والتشغيل التجريبي من متصفح اللاعب (**غير موثّق**: قد يُنقص ولا يرفع). يُرسَل للنموذج نص التحدي نفسه (الهدف والقواعد والميكانيكيات وطريقة الفوز ونوع المطلوب) ومعاييره بأوزانها، ويعطي كل معيار 0–10 مع سببه. **قواعد الأدلة** بحسب نوع المعيار تُطبَّق مهما قال: لا مدخلات ← التحكم ≤ 3 واللعب ≤ 5 · لا هدف (للعبة كاملة أو مستوى أو لغز) ← الاكتمال ≤ 5 · لا أثر لكلمات التحدي ← المطابقة ≤ 6 · أخطاء صياغة ← الاكتمال والتنفيذ ≤ 4 · نص يحاول توجيه المحكّم ← كل المعايير ≤ 5 · مشروع فارغ ← ≤ 1.5 … المحكّم لم يلعب اللعبة ولا يرى الصور، والصفحة تقول ذلك.
- **الحساب:** Σ(درجة المعيار × وزنه) ÷ 10 = الدرجة من 100، ثم /10. عدد المحكّمين من التعقيد، على مزوّدين مختلفين — **الوسيط** لكل معيار ثم درجة واحدة. النتيجة: score · feedback (الملخّص والسبب لكل معيار) · criteriaScores · completionStatus · الدرجة النهائية.
- **فشل الذكاء:** لا درجة وهمية ولا جائزة — «Judging Pending» مع السبب، ويُعاد بعد 2 · 10 · 30 · 60 · 180 · 360 دقيقة، وبعد 6 محاولات «تعذّر التحكيم» — يستطيع صاحب الموقع طلب تحكيمها من جديد قبل إعلان النتائج. كل مشاركة تُحكَّم مرة واحدة (قفل).
- **الفائز والوصيف:** الترتيب من درجات المحكّم وحدها — لا تصويت، ولا إعجابات، ولا اختيار يدوي. التعادل: معيار مطابقة التحدي ← أثقل معيار ← الاكتمال ← وإن بقي تعادل تامّ على جائزة: **مراجعة إضافية من NEXUS AI JUDGE** للّعبتين (سببها محفوظ ومعروض) ← الأسبق تسليمًا. تُعرض النتائج: Winner · Runner-up · Participants، و«▶ Play Winner Game».
- **الجوائز العامة (نقاط NEXUS):** الأولى من اقتراح AI ضمن حدود صاحب الموقع (200–10000)، الثاني 50% والثالث 25% منها، وكل مشاركة مُحكَّمة بعدهم 25 — ولا جائزة تحت 1/10. تُدفع بـ `points.js` نفسه (سطر «🏆 جائزة تحدٍّ») مع العلامة `challengeRewards/<entryId>` في الـcommit ذاته: **مرة واحدة**.

```
  ← المدة (اقتراح AI) · الجائزة من نقاطك (0 · 10 · 50 · 100 · 500 · 1000 أو أي رقم) · التوزيع · اللاعبون · من تدعو
  ← «إنشاء التحدي»: لا يُخصم شيء (تكلفة الإنشاء تظهر قبل التأكيد — 0 افتراضيًا) ← رابط الدعوة …/fc/<id> وتنبيه للمدعوّين
  ← ينضم الأصدقاء ← «▶ ابدأ» (صاحبه، لاعبان على الأقل): تُحجز الجائزة من رصيده في الـcommit نفسه الذي يبدأ التحدي
  ← يلعبون ويسلّمون ← انتهى الوقت: NEXUS AI JUDGE ← الفائز والوصيف ← توزيع الجائزة ← ما لم يُربح يعود لصاحبه
```
- **النقاط لا تُخصم قبل وقتها:** عند الإنشاء يُفحص الرصيد فقط (جائزة أكبر من رصيدك تُرفض قبل أن يُنشأ شيء). عند «ابدأ» تُحجز الجائزة (+ الرسوم إن وضعها صاحب الموقع) بسطر «🔒 جائزة تحدٍّ محجوزة» — مرة واحدة. الإلغاء قبل البدء: لم يُخصم شيء · بعد البدء وقبل أي تسليم: تعود كاملة · بعد تسليم: لا إلغاء، يُحكَّم عند انتهاء الوقت. التوزيع: الفائز يأخذ الكل · 70/30 · 50/30/20 — وما لم يُربح (لا تسليم صالح، أو درجة تحت الحد) يعود لصاحبه مرة واحدة.
- **الخصوصية والتلاعب:** `friendChallenges/<id>` يقرؤه صاحبه ولاعبوه والمدعوّون فقط، ولا يكتبه أي متصفح — ولا المعايير ولا الجائزة ولا اللاعبين ولا النتيجة. التنبيهات (دعوة، انضمام، بدء، إلغاء، نتيجة) يكتبها الخادم وحده: firestore.rules ترفض تنبيهًا من نوع `challenge` من أي متصفح. حدود لكل حساب يوميًا: 5 تحديات و10 أفكار من AI (قابلة للتغيير). الانضمام بالرابط قبل البدء فقط، والحد الأقصى للاعبين من الإعداد.
- **الإعدادات:** «🏆 NEXUS CHALLENGES ← الإدارة» (لصاحب الموقع: `ADMIN_EMAILS` ببريد مؤكَّد، أو صاحب صندوق المفاتيح) — أو متغيرات Netlify (قيم افتراضية تحت إعدادات اللوحة):

## 🌐 اللغات — العربية · English · हिन्दी
- **الواجهة كلها بلا خادم — `i18n/en.js` و`i18n/hi.js`:** قاموس كامل لكل نص عربي في `index.html` (≈4300 نص: الحساب، ➕ إنشاء، المحرّر، المساعد، الإعدادات، النقاط، التحديات، التشخيص… ورسائل دوال الخادم أيضًا). ملفات ثابتة: تعمل على أي استضافة — **حتى الرفع بالسحب والإفلات** حيث لا تعمل دوال Netlify (كان هذا سبب بقاء أماكن بالعربية). يُحمَّل ملف اللغة قبل أول رسم (لا وميض عربي)، ويُحمَّل عند تبديل اللغة دون إعادة تحميل، ويحفظه `sw.js` للعمل دون إنترنت. في الهندية كل الكلام بالهندية — تبقى بالحروف اللاتينية فقط AI وNEXUS والأسماء التجارية والكود.
- **النصوص التي تُصنع أثناء التشغيل** (أرقام، أسماء، أجزاء): تُطابَق بقوالب `{0}` (الأدق أولًا، والجزء الفارغ مسموح، ورقم قبل نص حين يتجاور جزءان)، ثم الأجزاء المفصولة بـ « · » و« — »، ثم «عنوان (3)» و«🎯 نص»، ثم الكلمات المعروفة داخل نص مختلط («HTTP (محلي) · 127.0.0.1»). ما ليس في القاموس يبقى كما هو — لا خليط مشوّه. أسماء اللاعبين والمشاريع وما يكتبه اللاعب لا تُترجم.
- **تلميحات الحقول** (placeholder/title لحقول النص) تُترجم أيضًا؛ ما يكتبه اللاعب داخلها لا يُمس. **اقتراحات المساعد** (الأزرار السريعة) بلغتك، وفقاعتها بعد الضغط بلغتك، والأمر نفسه يُنفَّذ كما هو.
- **نصوص التحديات** (يكتبها NEXUS AI بالعربية: العنوان، القصة، الهدف، القواعد، المعايير): الصفحة ترسل لغتها (`x-nexus-lang`) فيترجمها الخادم **مرة واحدة لكل لغة** بـ NEXUS AI ويحفظها على التحدي (`i18n_en` · `i18n_hi` مع بصمة النصوص) للجميع. تحدٍّ مع الأصدقاء كتبه صاحبه بنفسه (دون NEXUS AI) يبقى كما كتبه ولا يُرسل لأي نموذج.
- **الترتيب:** `translations.js` ← `i18n/<lang>.js` ← خدمة الترجمة `/api/i18n` لما ينقص فقط (ولا تُسأل أبدًا قبل وصول القاموس). **نص جديد في الواجهة:** أضفه في `phrases` داخل `translations.js`، أو أعد توليد ملفَي `i18n/` من نصوص `index.html`.
- **القاموس المركزي `translations.js`:** `keys` (مفتاح ← [عربي، إنجليزي، هندي]) لعناصر HTML ذات `data-i18n="KEY"` (و`data-i18n-placeholder` · `data-i18n-title`) ولـ `NX.t('KEY')` في الكود؛ و`phrases` (النص العربي كما هو في الواجهة ← [إنجليزي، هندي]) لبقية الواجهة: تُترجم لحظة ظهورها (مراقب DOM) — القوائم والأزرار والنوافذ والتنبيهات. لترجمة نص جديد: سطر واحد في `phrases`، دون أي تغيير آخر.
- **`setLanguage(lang)`** (`NX.setLanguage` · `window.setLanguage`): يغيّر كل النصوص فورًا بلا إعادة تحميل، ويضبط `dir` (rtl للعربية، ltr للإنجليزية والهندية) و`lang`، ويحفظ الاختيار في `localStorage` (`nx.lang`)، ويُطلق الحدث `nx:lang`. **أول زيارة:** لغة المتصفح (`navigator.languages`): عربي ← العربية، هندي ← हिन्दी، غيرهما ← English.
- **الهندية:** بالديفاناغاري كاملة — والمصطلحات التقنية أيضًا (गेम، प्रोजेक्ट، कोड، सेटिंग्स)؛ تبقى بالحروف اللاتينية فقط: AI وNEXUS وأسماء العلامات والكود. خط Hind يُحمَّل لمن يختار الهندية فقط.
- **الزر 🌐 في الشريط العلوي** (يظهر تحته: ع · EN · हि) وفي «الإعدادات ← اللغة والمظهر».
- **لا يُترجم أبدًا:** الكود ومحرّره، ما يكتبه اللاعب، وواجهة اللعبة نفسها (لها نظام ترجمتها `I18n` و`data-i18n` الخاص بها — مفاتيح غير موجودة في قاموس NEXUS لا تُمس).
- **الواجهة كلها — خدمة الترجمة `/api/i18n` (`netlify/edge-functions/i18n.js`):** نص من الواجهة ليس في `translations.js` يُترجمه NEXUS AI **مرة واحدة** (مفاتيح الموقع ومجمّعه) ويُحفظ للجميع في Firestore `i18n_cache` (لا يقرؤه ولا يكتبه أي متصفح)؛ الزائر التالي يأخذه فورًا من `GET /api/i18n/dict?lang=hi|en` دون أي طلب ذكاء، ويُحفظ في متصفحه أيضًا. الأرقام تُرسَل `{0}` فتُترجم الجملة مرة واحدة لكل الأرقام. **يُرسَل نص الواجهة فقط:** يجب أن تكون كلماته من كلمات كود NEXUS نفسه (≥85%) — اسم أو منشور أو محادثة لا تُرسَل أبدًا. الحدود اليومية: `I18N_PER_IP` (600 نص لكل زائر) و`I18N_DAILY` (30000 للموقع). يحتاج `FIREBASE_SERVICE_ACCOUNT` ومفاتيح الذكاء المجاني؛ بدونهما تبقى ترجمات `translations.js` كما هي.

## 🔁 Remix with AI — انسخ لعبة وعدّلها بالذكاء الاصطناعي (One-Click Remix & AI Fork)
- زر **«🔁 عدّل بالذكاء الاصطناعي · Remix with AI»** في شريط مشغّل اللعبة، وفي صفحة اللعبة، وفي صفحة تطبيقات HTML.
- `NX.Remix.remixProject(originalProjectId, currentUserId)`: يقرأ النسخة المنشورة كاملة (الكود، شجرة المشهد، الإعدادات، الوحدات المترجمة؛ الأصول بالمرجع لا بالنسخ) وينشئ **مشروعًا مستقلًا باسم اللاعب** فيه `remixedFrom` (صاحب الأصل، اللعبة، المشروع). الأصل يُقرأ فقط (+1 على عدّاد «remixes»)، ويُفتح المحرّر فورًا.
- **Remix Copilot:** يُفتح المساعد (والمجلس إن كان مفعّلًا) ومعه سياق اللعبة كاملًا وأزرار سريعة («غيّر سرعة السيارات»، «أضف سلاحًا جديدًا»، «عدّل إضاءة الخريطة»…)؛ التعديل يُطبَّق مباشرة وتُشغَّل المعاينة بعد كل تغيير (يمكن إيقاف ذلك من شريط Remix).
- **الأمان والحقوق (قواعد Firestore):** لا Remix إلا للعبة يسمح صاحبها بذلك (خيار عند النشر)، والإشارة للأصل لا تُغيَّر ولا تُحذف، واللعبة المنشورة من Remix تذكر أصلها («Remix من @صاحبها»)، والعدّاد يزيد بـ +1 فقط. كود لاعب آخر داخل Remix يعمل في الصندوق المعزول (Sandbox).
- كل نصوص Remix والمساعد مربوطة بمفاتيح الترجمة (`REMIX_*` بالعربية والإنجليزية والهندية).

## 🧩 الميكانيكيات (Mechanics) — ضعها على الأشياء، انسخها، احفظها
- في المحرّر: «🧩 الميكانيكيات» في قائمة العنصر المحدد. **نسخ** مكوّنات العنصر (بإعداداتها) وسكربتاته المرتبطة، ثم **لصق** على عنصر أو عدة عناصر — خطوة تراجع واحدة.
- **حفظ في «ميكانيكياتي»** باسم ووصف، خاصة أو عامة؛ و**المكتبة**: ميكانيكياتي + العامة من المطوّرين الآخرين، تُضاف إلى أي مشروع (+1 استعمال لصاحبها).
- NEXUS Learner يتعلّم منها (ميكانيكيات المطوّرين البشريين المنشورة).

## 🎓 «كيف أبرمج؟» — معلّم NEXUS AI الحي
```
الاستوديو ← المزيد ← «🎓 كيف أبرمج؟» (أو 🎓 في شريط محرر الكود، أو لوحة الأوامر)
  ← «هل تسمح للذكاء الاصطناعي بفتح القوائم وكتابة الكود أمامك لتوضيح طريقة البرمجة؟» [موافق / إلغاء]
  ← مؤشر NEXUS AI يفتح «الأصول» ← يضيف مكعب «Player» للمشهد ← يفتح محرر الكود
  ← يكتب حرفًا حرفًا في ملف درس جديد (Tutor_Lesson.js): المتغيرات · start() وزر JUMP مربوط باللعبة · update(dt) والحركة
  ← يشغّل اللعبة ← «خروج وتجربة الكود بنفسي»: الكود مفتوح في المحرر لتعدّله وتضغط RUN
```
- **بلا موافقة لا شيء:** «إلغاء» يترك القسم دليلًا مقروءًا (المتغيرات، أوامر الحركة، ربط الأزرار). يكتب في ملف درس جديد داخل المشروع فقط — لا يغيّر ملفات اللاعب.
- **فقاعة شرح** فوق كل خطوة وحلقة ضوئية حول ما يتحدث عنه، و**شريط تحكم**: ⏸/▶ إيقاف وتشغيل · ⟲ أعد الخطوة (يمحو ما كتبته ويكتبها من جديد) · ⏭ الخطوة التالية (تُكمَل فورًا) · السرعة 1x ← 2x ← 0.5x · 🏁 خروج وتجربة الكود بنفسي.
- **اللغات:** كل الشرح وتعليقات الكود بلغة الواجهة؛ تغيير اللغة أثناء الدرس يغيّر الفقاعة والشريط فورًا، والخطوة المعادة تُكتب باللغة الجديدة.
- **درس من NEXUS AI لسؤالك:** اكتب سؤالك («كيف أجعل اللاعب يقفز؟») فيُعدّ NEXUS AI درسًا بالخطوات نفسها — عبر عميل الذكاء نفسه (`NX.AIClient`، مزوّدو الموقع ومفاتيحه) وبلغة الواجهة، ويُكتب كوده أمامك ولا يُشغَّل إلا حين تشغّله أنت. إن لم يُجب الذكاء يبقى الدرس المدمج.
- **الكود حقيقي:** نفس واجهات NEXUS (UI.text/UI.button/Input.axis/Scene.find/Audio.beep) — يُبنى ويعمل في المحرك (الاختبار يتحقق من ظهور زر JUMP والنقاط أثناء اللعب).
- ملاحظة: لا يوجد في NEXUS محرّر عُقد مرئي (Logic Nodes) — يفتح المعلّم ما هو موجود: الأصول، المشهد، ومحرر الكود.

## صندوق السكربتات (Sandbox)
ألعاب الآخرين المنشورة وكل مشروع فيه فريق تعمل داخل `iframe sandbox` بمصدر مجهول. هذا الصندوق لا يصل إلى:
- جلسة دخولك؛
- تخزين الموقع؛
- مفاتيح AI؛
- Firebase.

الغرف والحفظ والأصول ولوحة الصدارة تمرّ عبر جسر يتحقق من كل طلب. مشروعك الفردي وألعابك أنت تعمل كما كانت.

## الدخول بمفتاح المرور (Passkeys) — اختياري
Firebase Authentication لا يدعم مفاتيح المرور بنفسه، لذلك تتولّاها الدالة `netlify/edge-functions/passkeys.js`. لتفعيلها:
1. Firebase Console ← Project settings ← Service accounts ← **Generate new private key**.
2. Netlify ← Site configuration ← Environment variables ← أضف `FIREBASE_SERVICE_ACCOUNT` والصق ملف JSON كاملًا.
3. أعد النشر (يحتاج نشرًا مربوطًا بـ Git حتى تعمل الدوال).

بدون هذا المتغير لا يظهر زر Passkey، ويبقى الدخول بـ Google والبريد كما هو. لا تضع ملف حساب الخدمة في المستودع ولا في index.html أبدًا.

## تطبيقاتي ومواقعي (HTML)
- من «مشاريعي» ← «تطبيقاتي ومواقعي · HTML» ← «رفع»: ملف ‎.html‎ واحد، أو عدة ملفات معًا (html · css · js · صور · أصوات · خطوط · json)، أو ملف ZIP لموقع كامل فيه index.html (حتى 25 MB و 800 ملف). على الكمبيوتر يمكن رفع مجلد.
- يُقرأ اسم التطبيق من `<title>` وأيقونته من `<link rel="icon">`، وتختار: عام (يظهر في الصفحة الرئيسية «تطبيقات ومواقع») أو برابط فقط أو خاص. «تجربة قبل الرفع» تشغّله قبل أن يُرفع.
- يعمل داخل NEXUS كما هو: الروابط بين صفحاته، ملفات CSS و JS، وحدات ES (`import './x.js'`)، الصور والخطوط، `fetch('data.json')`، و localStorage (يُحفظ في متصفح كل زائر لكل تطبيق).
- رابط المشاركة: `https://موقعك.netlify.app/app/<appId>` (أو `…/#app/<appId>`).
- **الأمان:** كل تطبيق يعمل في `<iframe sandbox>` بدون allow-same-origin — أصل معزول لا يصل إلى حسابك ولا إلى Firebase ولا إلى تخزين الموقع، ولا يستطيع تغيير صفحة NEXUS. تطبيقات الآخرين تُعرض مع تنبيه «لا تكتب فيه كلمة مرور». الرفع لأصحاب الحسابات فقط (لا لجلسة الضيف)، والملكية والظهور والعدّاد تفرضها firestore.rules و storage.rules.
- انشر القواعد والفهارس الجديدة: `firebase deploy --only firestore,storage`.
- **الأيقونة والصورة:** لكل تطبيق أيقونة (في القوائم) وصورة (في بطاقته وأعلى صفحته). تُؤخذ من ملفاته إن وُجدت (`<link rel="icon">`، و `og:image` أو ملف مثل cover/screenshot)، أو ترفعها أنت في نافذة الرفع، وإلا تُرسم من الاسم والأيقونة (وتقول النافذة ذلك). تغيّرهما لاحقًا من صفحة التطبيق: «أيقونة التطبيق» و «صورة التطبيق».
- **✎ تعديل الملفات والكود** (لصاحب التطبيق، من صفحته): قائمة الملفات، محرّر كود لكل ملف نصي (html · css · js · json · svg …)، استبدال صورة أو صوت (مثل شخصية لعبة 2D)، إضافة وإعادة تسمية وحذف ملفات، «▶ تشغيل» يجرّب التعديلات في نفس الصندوق المعزول قبل الحفظ، «🤖 الذكاء» يكتب تعديلًا يظهر كفرق (diff) أولًا ثم «تطبيق» أو «إلغاء» و«↶ تراجع»، و«💾 حفظ» يرفع نسخة جديدة بنفس الرابط والأيقونة والصورة. ألعاب HTML تُعدَّل بالكود — محرّر المشهد المرئي للألعاب المصنوعة داخل NEXUS.

## الأيقونة والصورة عند نشر لعبة
- نافذة النشر فيها «الأيقونة والصورة»: «رفع أيقونة» (تُقصّ مربّعة) و«رفع صورة» من جهازك، أو «من المشهد» / «التقاط الآن». ما ترفعه يُحفظ في «وسائط اللعبة» ويظهر فورًا على اللعبة المنشورة.
- إن لم تختر شيئًا تُلتقط الاثنتان من المشهد عند فتح النافذة وتراهما قبل النشر — فلا تُنشر لعبة بلا أيقونة ولا صورة.

## الفئة العمرية (3+ · 7+ · 12+ · 16+ · 18+)
- **من يحدّدها:** عند النشر أو رفع تطبيق (وعند حفظ تعديلات تطبيق) يُفحص المحتوى: الاسم والوصف والوسوم وأسماء الكائنات والملفات والنصوص التي يراها اللاعب في الكود. وإذا كان الذكاء متصلًا يقرأ النموذج نفس الأشياء ويقترح فئة وأسبابًا. الأعلى بين الاثنين هو **أقل** ما يمكن اختياره (الخيارات الأقل تُقفل)، وتستطيع اختيار أعلى. الفحص والنموذج لا يريان الصور ولا يلعبان اللعبة — تظهر الأسباب لتراجعها.
- **من يلعب:** 3+ للجميع حتى من لم يسجّل الدخول. ما فوق 3+ يحتاج حسابًا (Google أو البريد) وشهر وسنة الميلاد — تُسأل مرة واحدة، تُحفظ في `ages/{uid}`، لا يراها غير صاحبها، ولا تُغيَّر أو تُحذف من المتصفح (الخطأ يصحّحه صاحب الموقع من لوحة Firebase). من عمره أقل لا تُفتح له اللعبة ولا تظهر في قوائمه.
- **العمر مرتبط بالحساب لا بالجهاز، ومحسوب لا مخزَّن:** عند **إنشاء حساب جديد** (البريد أو Google) يُسأل شهر وسنة الميلاد فورًا (اختياري: «ليس الآن»). يُحفظ في `ages/{uid}` السنة والشهر فقط — لا يوم ولا رقم «عمر» ثابت — ويُحسب العمر في كل مرة: في الصفحة من تاريخ اليوم، وفي firestore.rules من `request.time`. فمن كان 15 يصبح 16 وحده حين يأتي شهر ميلاده، ويرى الهاتف الثاني الذي يدخل الحساب نفسه العمر نفسه (لا شيء منه في localStorage). النظام لم يكن يخزّن «age» رقمًا من قبل، فلا شيء يُحوَّل.
- **على الخادم:** firestore.rules لا تعطي ملف اللعبة القابل للتشغيل (`builds`) ولا storage.rules ملفات التطبيق إلا لمن يسمح عمره بذلك (الصور والبطاقات تبقى ظاهرة). في وضع تخزين الملفات على Google Drive لا تنطبق storage.rules على ملفات Drive — الحماية هناك في الواجهة فقط (ملف اللعبة في Firestore يبقى محميًا).
- **تنبيه صادق:** تاريخ الميلاد كلمة اللاعب نفسه، وليس تحققًا من الهوية. الموقع «القانوني المتكامل» يحتاج أيضًا سياسة خصوصية وشروط استخدام، وموافقة وليّ الأمر للأطفال حيث يفرضها القانون (مثل COPPA في أمريكا و GDPR في أوروبا) — هذه قرارات ونصوص قانونية لصاحب الموقع، لا يكفي الكود وحده.
- قواعد firestore.rules لا تقبل إلا 3 أو 7 أو 12 أو 16 أو 18. انشر القواعد: `firebase deploy --only firestore:rules,storage`.

## 🎯 المساعد يعمل على العنصر المحدد (Editor Agent)
حدّد عنصرًا في المشهد (أو اضغط ✨ «اسأل الذكاء» في شريط التحديد) ثم اكتب ما تريد. أعلى المساعد: **🎯 الهدف** (العنصر المحدد) و**النطاق** (تلقائي · العنصر المحدد · المشهد الحالي · اللعبة الحالية · المشروع كاملًا) واقتراحات تناسب العنصر.
- **تعديلات مباشرة:** «صغّرها شوي» · «هذه السيارة كبيرة، صغرها شوي» · «السيارة معلقة في الهواء، خليها على الأرض» · «اجعل دورانها صحيحاً» · «غيّر مكانها» · «غيّر لونها إلى الأزرق» (يعمل على المجسمات المستوردة أيضًا ويبقى بعد إعادة الفتح) · «اجعلها لا تمر من خلال الأرض» · «أصلح الاصطدام».
- **التشخيص:** «هذه السيارة لا تعمل» / «ما مشكلتها؟» يفحص الحجم والموضع والدوران، ملف المجسم، المكوّنات وملفاتها، السكربتات المربوطة والتي تبحث عنها بالاسم، من يحرّكها، الجسم الفيزيائي، ما تحتها، أخطاء الكود والتشغيل — ثم **يشغّل اللعبة 1.6 ثانية مع الضغط على التسارع ويقيس هل تحرّكت فعلًا**. يقول السبب («لا يوجد أي كود أو مكوّن يحرّكها»، «السكربت يبحث عن Car لكن اسمها Car 2»…) ويقترح الإصلاح. «أصلح حركة السيارة» يصلح ويختبر مباشرة.
- **السرعة:** «اجعلها أسرع» · «اجعل هذه السيارة فقط أسرع» · «خل السيارات كلها تمشي أسرع» — يجد السرعة الحقيقية (إعدادات المكوّن أو ثوابت السكربت مثل MAX_SPEED) ويعرض Max Speed: 24 → 31.2 قبل/بعد.
- **أنظمة جاهزة (ملفات حقيقية تفتحها وتعدّلها):** «اجعلها قابلة للقيادة باللمس» (VehicleController) · «أضف لها نظام بنزين» (Fuel — محطة الوقود أي كائن tag = fuel) · «اجعلها تتبع الطريق» (FollowPath — نقاط من الطريق) · «اجعل هذا العدو يطارد اللاعب» (ChaseTarget) · «اجعل هذا الباب يفتح عندما يقترب اللاعب» (DoorProximity) · «عندما يموت اللاعب أعده إلى نقطة البداية» (Respawn) · «اجعل جميع السيارات تتوقف عندما ينتهي السباق» (RaceEnd + خط نهاية إن لم يوجد) · «أضف Multiplayer» / «اجعل اللاعبين يرون بعضهم».
- **اللعب الجماعي:** غرف عبر Network.room (العب مع الجميع · غرفة خاصة برمز · انضمام برمز)، مزامنة الموقع والدوران والحالة، ظهور اللاعبين الآخرين بنفس المجسم، أحداث بين اللاعبين (`Events.emit("NetEmit", …)`). **يحتاج:** اتصال الموقع بالسحابة واللاعب داخلًا (الضيف يكفي) — لا خادم ولا مفتاح إضافي. المساعد يقول بوضوح إن كان متاحًا الآن أم لا.
- **المعاينة والتطبيق:** كل تغيير يظهر كبطاقة: Target · Scope · Action · Changes (قبل → بعد). الصغير والواضح يُنفَّذ مباشرة؛ غيره Apply / Cancel؛ الكبير (ملفات أو أنظمة كثيرة) يعرض عدد الملفات والمكوّنات والأنظمة مع **Review Changes** (الملفات سطرًا بسطر) و**Apply All**.
- **↩ Undo AI Change / ↪ Redo AI Change:** على بطاقة النتيجة، ومن «↩ تغييرات AI» أعلى المساعد، أو بكتابة «تراجع عن تغيير الذكاء الاصطناعي». قبل كل تغيير تُحفظ نسخة من المشهد والملفات والمكوّنات؛ التغييرات الكبيرة تُنشئ أيضًا نقطة رجوع في «تاريخ المشروع».
- **مع نموذج متصل** يستطيع النموذج طلب نفس الأنظمة (ADD_SYSTEM · SET_COMPONENT · SET_BODY · SNAP_TO_GROUND · FIX_ROTATION)، وكل طلب يُفحص ويُعرض قبل التطبيق.
- إصلاح: نوع الجسم الذي تختاره في الخصائص (Physics ← Body type / «فيزياء») صار يُطبَّق فعلًا عند التشغيل — كان يُحفظ ولا يعمل.
- لا يخترع: إن لم يوجد العنصر أو النظام سأل أو قال ذلك؛ ولا يضيف نظامًا فوق كود كتبته أنت لنفس الشيء (يعدّله النموذج بدلًا من ذلك).
- **يستعمل أدوات المحرّر نفسها:** «انسخ هذا المبنى خمس مرات وضعها على شكل دائرة» (نسخ حول المبنى، كلها تواجه المركز) · «كرر الشجرة 4 مرات في صف كل 3 م» · «اعمل 9 نسخ شبكة» · «كبر هذه الأرض واجعلها أعلى قليلاً» (×1.25 و+0.5 م) · «ارفعها 2 متر قليلا» · «ضع هذه الشجرة بجانب الطريق» (بجانب الطريق عند مكانها، لا عند طرفه البعيد). النموذج المتصل يستطيع أيضًا ARRAY_OBJECT و DUPLICATE_OBJECT. كل طلب خطوة تراجع واحدة.

## ✎ المحرّر ثلاثي الأبعاد على الهاتف (Studio)
نفس المحرّر ونفس المشهد — طُوّر ولم يُستبدل: التحديد والتحويل في المحرك (PART 4)، سجل التراجع في الاستوديو (PART 7)، والواجهة في PART 35.
- **الشريط السفلي:** ➕ إنشاء · ✎ رسم · ↶ تراجع · ↷ إعادة · 🧲 Snap · ☑ تحديد متعدد · 🗂 المشهد · ▦ أدوات. وضع المبتدئ يعرض الأساسيات فقط (إنشاء، رسم، تراجع، إعادة، الأصول).
- **على المجسم:** مقابض كبيرة ملوّنة — أسهم للنقل على محور (والمربع/الكرة في الوسط للنقل على الأرض)، حلقات للتدوير، مكعبات للحجم (والمكعب الأوسط للحجم كله). اسحب المجسم نفسه لتحريكه. **إصبعان على المجسم:** قرص = تكبير/تصغير، لفّ = تدوير. إصبعان خارجه = الكاميرا. **ضغطة مطوّلة** = قائمة المجسم. لمسة = تحديد.
- **شريط التحديد:** نقل / تدوير / حجم، ⧉ تكرار (النسخة بجانب الأصل تمامًا — الجدران تتصل)، ⋯ القائمة: تكرار ونقل، حذف، المادة واللون، محرّر الشكل، على الأرض، إعادة ضبط (الموضع/الدوران/الحجم/الكل)، قفل، إخفاء، نسخ متعدد (صف/دائرة/شبكة)، نسخ/لصق، تجميع/فكّ التجميع، محاذاة، توزيع، توسيط، تركيز.
- **إنشاء:** مكعب، كرة، أسطوانة، مخروط، كبسولة، أرضية، حلقة مجوّفة (Torus)، دائرة، حلقة (Ring)، مستطيل — وأضواء وكاميرا ونقطة بداية ومجموعة فارغة. كل شكل جزء حقيقي من المشهد ويُحفظ مع اللعبة.
- **الرسم بالإصبع:** ارسم دائرة أو مستطيلًا أو خطًا أو شكلًا مغلقًا أو مسارًا؛ يتعرّف عليه ويعرضه معاينةً في المشهد، ثم «➕ أضف إلى اللعبة» (أو «كما رسمته» ليبقى كما هو).
- **محرّر الشكل:** العرض والارتفاع والعمق ونصف القطر والسُّمك والتقسيمات والدوران والموضع والحجم — يتغيّر مباشرة. **Extrude:** دائرة → أسطوانة، مستطيل → صندوق، شكل مغلق → مجسم مرفوع (شريط «الارتفاع»).
- **محرّر المادة:** 16 لونًا + منتقي لون، معدني، خشونة، شفافية، توهّج وقوته، وصورة من أصولك على السطح مع تكرارها. للأضواء: اللون والشدّة.
- **المشهد (Hierarchy):** مجموعات: البيئة، اللاعب، الأشكال، المجسمات، المجموعات، الإضاءة، الكاميرات، الأصوات، الواجهة — مع بحث، وقفل وإظهار لكل عنصر، وضغطة مطوّلة للقائمة.
- **الخصائص (Inspector):** النوع، ظاهر، مقفل، الأب (Parent)، المادة، الشكل، Collider — فوق الموضع والدوران والحجم والفيزياء والسكربتات الموجودة.
- **Snap:** خطوة الشبكة للنقل، خطوة الدوران بالدرجات، خطوة الحجم — قابلة للتعديل وتُحفظ.
- **التراجع والإعادة:** كل عملية (نقل، تدوير، حجم، إنشاء، حذف، تجميع، مادة، شكل، قفل، إخفاء…) خطوة واحدة؛ حتى 100 خطوة. التعديلات الصغيرة تُحفظ كتغييرات للعناصر المتأثرة فقط (لا نسخة كاملة من المشهد في كل خطوة). اختصارات لوحة المفاتيح: Ctrl+Z / Ctrl+Y / Ctrl+D / Ctrl+C / Ctrl+V / Ctrl+G / Delete / W E R / F.
- **حفظ تلقائي** بعد 4 ثوانٍ من آخر تعديل (والحفظ كل 30 ثانية باقٍ). تاريخ المشروع (Version History) كما هو.
- **▶ تشغيل · ⏸ إيقاف مؤقت · ⏹ إيقاف · 🔄 من جديد:** شارة «وضع التعديل / وضع اللعب» أعلى المشهد. الإيقاف يعيد المشهد كما عدّلته تمامًا (ما يغيّره اللعب لا يبقى).
- **الأداء:** تغيير الشكل أو المادة يعيد بناء ذلك العنصر وحده.
- **حدود صريحة:** الرسم يضع الشكل على أرض العالم (y = 0)؛ الـCollider صندوق حول المجسم (AABB) كما في المحرك؛ واجهة اللعبة (النصوص والأزرار) تُصنع بالكود `UI.text(…)` وليست عناصر في المشهد.

## توفير الرموز (Tokens) — ردود أسرع ومفاتيح تدوم أكثر
- التحية («سلام»، «شكرًا») تُرسل بلا بيانات المشروع: ~380 حرفًا بدل ~12,800، ومساحة رد 800 بدل 4000.
- السؤال يُرسل ملخص المشروع فقط (الأسماء والأنظمة والعنصر المحدد، وواجهات المحرك عند الحاجة)؛ طلب التعديل وحده يُرسل الصورة الكاملة.
- المحادثة السابقة تُختصر: آخر 6 رسائل، والكود الطويل في الردود القديمة يصبح «[كود: N سطر]».
- الكود المرتبط بالسؤال فقط؛ إن لم يطابق شيء يُرسل ملف واحد قصير لا اثنان طويلان.
- إن قُطع رد قصير عند الحد الصغير يُعاد مرة واحدة بالحد الكامل (لا يضيع الجواب).
- في قياس على مشروع حقيقي (6 رسائل متنوعة): 81,578 حرفًا → 29,440 (−64%).
